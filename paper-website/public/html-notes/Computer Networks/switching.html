1. Introduction to Switching

Switching is the process of forwarding packets from one port to another port within the network. It is primarily a function of the Network Layer (with exceptions).

2. Circuit Switching

Physical Layer

Designed originally for telephone networks. A dedicated physical path is established before communication begins and remains reserved for the duration.

The 3 Phases

  1. Setup Phase: Circuit establishment. Resources (buffers, switch ports, bandwidth) are reserved.
  2. Data Transfer: Continuous flow of data. No addressing needed in headers (path is fixed).
  3. Teardown Phase: Disconnect signal sent to release resources.

Total Time Calculation

$$ Total Time = T_{setup} + T_{transmission} + T_{propagation} + T_{teardown} $$

Note: Setup takes substantial time across all hops.

3. Packet Switching

Network Layer

The message is broken into smaller chunks called packets. Uses Store and Forward technique. No resource reservation.

Key Mechanism: Pipelining

Dividing the message allows the first packet to move to the second node while the first node processes the second packet. This parallelism reduces total time.

Pros
  • Efficient bandwidth usage
  • Fault tolerant (packets can reroute)
  • No setup delay
Cons
  • Out of order delivery
  • Header overhead per packet
  • Queueing & Processing delays

4. Delay Formulas & Pipelining

Standard Notation

  • $X$: Number of Hops (Links)
  • $N$: Number of Packets
  • $T_t$: Transmission Delay ($Size / Bandwidth$)
  • $T_p$: Propagation Delay ($Distance / Speed$)
  • $T_{proc}$: Processing Delay
  • $T_{qd}$: Queueing Delay

General Formula (Store & Forward with Pipelining)

Time for the first packet to travel strictly through all hops + Time for remaining packets to clear the pipeline.

$$ Total Time = \underbrace{X \cdot (T_t + T_p + T_{proc} + T_{qd})}_{\text{First Packet to Dest}} + \underbrace{(N-1) \cdot T_t}_{\text{Remaining Packets}} $$

Logic: The first packet clears the path. Once the pipeline is full, a new packet emerges from the destination every $T_t$ seconds (assuming $T_t$ is the bottleneck).

5. Optimal Packet Size

If packets are too small, header overhead dominates. If packets are too large, pipelining benefits are lost. There is a "Goldilocks" zone.

Variables:
  • $M$: Total Message Size
  • $h$: Header size per packet
  • $p$: Payload (data) size per packet
  • $X$: Number of Hops
Packet Size $P = p + h$
Number of Packets $N = M/p$

The Optimization Formula

$$ p_{optimal} = \sqrt{\frac{M \cdot h}{X - 1}} $$

Actual Optimal Packet Size = $p_{optimal} + h$

Derivation Logic (Click to Expand)

1. Total Transmission Time equation:

$$ TT = \left(\frac{p+h}{b}\right)X + \left(\frac{M}{p}-1\right)\left(\frac{p+h}{b}\right) $$

2. Differentiate $TT$ with respect to $p$ (payload size) and set to 0.

$$ \frac{d}{dp}TT = 0 \Rightarrow p^2 = \frac{Mh}{X-1} $$

6. Circuit vs. Packet Switching

Feature Circuit Switching Packet Switching
Phases 3 (Setup, Data, Tear) 1 (Data Transfer)
Path Physical, Dedicated Virtual, Dynamic
Order In-order arrival Out-of-order possible
Bandwidth Reserved (Wastage if idle) Dynamic (Efficient)
Reliability High (once setup) Lower (congestion/loss)

7. Solved Problems (GATE)

Q1. Effect of Packetization on Time (GATE 2014)

Scenario: Send file size $10^3$ bytes. Bandwidth $10^6$ B/sec. Header 100 bytes. Compare 3 cases: 1 packet, 10 packets, 20 packets.

Case 1 (1 Pkt):
Data+H = 1100B
Time $\approx 3.3ms$
Case 2 (10 Pkts):
Data=100B, H=100B
Total $\approx 2.1ms$ (Best)
Case 3 (20 Pkts):
Data=50B, H=100B
Time $\approx 3.3ms$ (Overhead high)

Conclusion: $T_2 < T_1 = T_3$. Increasing packets helps up to a limit where header overhead takes over.

Q2. Calculating Optimal Packet Size (GATE 2005)

Given: Message $M=24$ bytes. Header $h=3$ bytes. Path has 2 intermediate nodes ($X=3$ hops).

p = sqrt(M*h / X-1)
p = sqrt(24*3 / 2)
p = sqrt(36) = 6 bytes (payload)

Total Optimal Packet Size: $p + h = 6 + 3 = \mathbf{9 \text{ bytes}}$.

Q3. Pipeline Delay Calculation

Given: File $10^6$ bits. 2 Routers ($X=3$). BW $1$ Mbps. Pkt size $1000$ bits. Link length $100$km, Speed $10^8$ m/s.

  • $T_t$ (Transmission) = $1000 / 10^6 = 1$ ms
  • $T_p$ (Propagation) = $100km / 10^8 = 1$ ms
  • Number of Packets $N = 1000$
$$ Time = X(T_t + T_p) + (N-1)T_t $$ $$ Time = 3(1+1) + (999 \times 1) $$ $$ Time = 6 + 999 = \mathbf{1005 \text{ ms}} $$
