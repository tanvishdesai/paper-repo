1. Introduction & The Need for Synchronization

Fundamentals

Synchronization is the coordination of processes in an IPC (Inter-Process Communication) environment to ensure order and prevent data inconsistency.

  • Independent Processes: No shared state. Execution of one does not affect another.
  • Cooperating Processes: Share resources (memory, variables). Execution of one affects others.

Consequences of Lack of Sync:

  • ❌ Inconsistency: Shared data becomes corrupted (Race Condition).
  • 📉 Data Loss: Updates are overwritten.
  • 🔒 Deadlock: Processes wait indefinitely for each other.

2. The Critical Section (CS) Problem

A system of $n$ processes must share resources. The segment of code where a process accesses shared resources is called the Critical Section.

1. Mutual Exclusion (Primary)

If process $P_i$ is executing in its CS, no other processes can be executing in their CS.

2. Progress (Primary)

If no process is in CS, only processes not in Remainder Section can decide who enters next. Selection cannot be postponed indefinitely.

3. Bounded Waiting (Optional)

There exists a bound on the number of times other processes enter CS after a request is made by a process.

do {
  <Entry Section> // Request permission
    CRITICAL SECTION // Access shared resource
  <Exit Section> // Notify exit
    REMAINDER SECTION
} while (true);

3. Software Solutions (2 Processes)

Attempt 1: Lock Variable Fails Mutual Exclusion 
while(lock != 0); // Busy Wait
lock = 1;         // Set Lock
// Critical Section
lock = 0;         // Release

Why it fails: The check lock != 0 and set lock = 1 are not atomic.

If P1 reads lock as 0, gets preempted, then P2 reads lock as 0, both enter CS.

Attempt 2: Strict Alternation (Turn Variable) Fails Progress
Process 0
while(turn != 0);
// CS
turn = 1;
Process 1
while(turn != 1);
// CS
turn = 0;

Why it fails: Enforces strict order $P_0 \to P_1 \to P_0$. If $P_0$ doesn't want to enter, $P_1$ is blocked indefinitely (Violation of Progress).

✅ Peterson's Solution

Satisfies ME, Progress, Bounded Wait

Combines the concepts of turn (Strict Alternation) and flag[] (Interest). It assumes LOAD and STORE instructions are atomic.

Algorithm for Process i
void enter_region(int i) {
    int j = 1 - i; // The other process
    flag[i] = TRUE; // I am interested
    turn = j;       // I offer turn to you
    
    // Wait if other is interested AND it's their turn
    while (flag[j] == TRUE && turn == j); 
}

void leave_region(int i) {
    flag[i] = FALSE; // I am done
}
Logic Analysis:
  • Mutual Exclusion: Both can't pass the while loop because turn can only be 0 or 1 at a specific instant.
  • Progress: If P1 is not interested (flag[1]==F), P0 enters immediately.
  • Bounded Wait: P0 will enter at most after one entry of P1.
⚠️ Note: Only works for 2 processes. Based on Busy Waiting (wastes CPU cycles).

4. Hardware Support

Hardware provides special Atomic Instructions that execute non-preemptively (in one bus cycle).

Test and Set Lock (TSL)

Reads a word from memory and writes '1' (TRUE) to it atomically.

boolean TSL(boolean *target) {
    boolean rv = *target;
    *target = TRUE;
    return rv;
}

// Usage
while (TSL(&lock)); // Spin
// CS
lock = FALSE;

Swap Instruction

Swaps contents of two memory words atomically.

void Swap(bool *a, bool *b) {
    bool temp = *a;
    *a = *b;
    *b = temp;
}

// Usage
key = TRUE;
while (key == TRUE) Swap(&lock, &key);
// CS
lock = FALSE;

Priority Inversion: A side effect of busy-waiting hardware locks. A low-priority process holds the lock, pre-empted by a high-priority process which then spins waiting for the lock. The CPU is wasted spinning, and the low-priority process never gets CPU to release the lock.

5. Semaphores

OS Primitive

A synchronization tool that provides a more sophisticated way (than locks) for process synchronization. It is an integer variable accessed only via two atomic operations.

Wait (P / Down)

Used to acquire a resource.

wait(S) {
    S.value--;
    if (S.value < 0) {
        add process to S.queue;
        block(); // Sleep
    }
}

Signal (V / Up)

Used to release a resource.

signal(S) {
    S.value++;
    if (S.value <= 0) {
        remove P from S.queue;
        wakeup(P); // Ready
    }
}

Types of Semaphores

Type Range Usage
Binary Semaphore (Mutex) 0, 1 Solving Critical Section, Mutual Exclusion.
Counting Semaphore Any Integer Resource Management (e.g., 5 printers).

⧉ Calculation Trick

If $S$ is initialized to $N$, and we perform $P$ (wait) operations $x$ times and $V$ (signal) operations $y$ times:

Current Value = $N - x + y$
  • If Value $> 0$: Number of available resources.
  • If Value $\le 0$: Magnitude is the number of blocked processes.

6. Classical IPC Problems

1 Producer-Consumer (Bounded Buffer)

Producer puts items in buffer, Consumer takes them. Buffer size $N$.

Shared Variables:
Semaphore mutex = 1;
Semaphore empty = N;
Semaphore full = 0;
Producer 
while(true) {
 item = produce();
 wait(empty);
 wait(mutex);
 // add item
 signal(mutex);
 signal(full);
}
Consumer 
while(true) {
 wait(full);
 wait(mutex);
 // remove item
 signal(mutex);
 signal(empty);
 consume(item);
}

2 Readers-Writers Problem

Multiple readers can read simultaneously. Writer needs exclusive access (no readers, no other writers).

graph TD W[Writer] -- Requires --> Mutex[DB Lock] R1[Reader 1] -- Requires --> Mutex R2[Reader 2] -- Requires --> Mutex R1 -. Concurrent .- R2 W -. Exclusive .- R1
Logic: First reader acquires the lock for all readers. Last reader releases it.

3 Dining Philosophers

5 philosophers sit at a table. 5 forks. Need 2 forks to eat.

Deadlock Scenario:

If everyone picks up the left fork simultaneously, everyone waits for the right fork forever.

Solutions:
  • Allow at most 4 philosophers at the table.
  • Pick up forks only if both are available (Critical Section).
  • Asymmetry: Odd philosophers pick Left then Right; Even pick Right then Left.

7. Concurrency & Precedence

Constructs

Fork L;

Creates a new process starting at label L.

Join N;

Allows $N$ processes to merge. The first $N-1$ processes terminate/wait. The $N^{th}$ process continues.

Parbegin / Parend

Executes statements between them concurrently.

parbegin 
  S1; 
  S2; 
parend

Bernstein's Conditions

Two processes $P_1$ and $P_2$ can execute concurrently (in parallel) if:

$$ R(P_1) \cap W(P_2) = \emptyset $$ $$ W(P_1) \cap R(P_2) = \emptyset $$ $$ W(P_1) \cap W(P_2) = \emptyset $$

Where R is Read Set and W is Write Set.
