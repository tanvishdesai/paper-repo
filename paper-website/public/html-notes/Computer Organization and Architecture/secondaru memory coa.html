1. Cache Updating Techniques

When the CPU performs operations, we must ensure consistency between Cache Memory (CM) and Main Memory (MM). This is the Cache Coherence problem.

Write Through (WT)

Update both Cache and Main Memory simultaneously.

  • Pro Simple, High Consistency.
  • Con Slow (Speed limited by MM).
  • Access Read Miss: Read Allocate. Write Miss: No Write Allocate (typically).

Write Back (WB)

Update only Cache. Update MM only when the block is replaced.

  • Pro Fast (Updates happen at Cache speed).
  • Con Complex hardware (Dirty Bit).
  • Hardware Requires Dirty Bit (Modified Bit).

Performance Formulas

Simultaneous Access:
$$ T_{avg\_read} = h_r \cdot T_c + (1-h_r) \cdot T_m $$ $$ T_{avg\_write(WT)} = T_m \quad \text{(Assuming simultaneous update)} $$
Write Back Average Access:
$$ T_{avg} = h \cdot T_c + (1-h) \cdot [\%_{dirty} \cdot (T_{wb} + T_{new}) + \%_{clean} \cdot T_{new}] $$ Where \(T_{wb}\) is time to write back dirty block, \(T_{new}\) is time to fetch new block.

2. Disk Structure & Design

Magnetic disks are the bulk secondary storage. They are electromechanical devices.

graph TD A[Disk Drive] --> B[Platters] B --> C[Surfaces] C --> D[Tracks] D --> E[Sectors] E --> F[Data + Header + CRC] style A fill:#e0f2fe,stroke:#2563eb style D fill:#dcfce7,stroke:#059669 style E fill:#fef9c3,stroke:#d97706

Hierarchy Definitions

  • Platter: Circular magnetic plate. Has 2 surfaces (Upper/Lower).
  • Cylinder: The set of tracks at the same arm position across all surfaces. This reduces seek time for large files.
  • Track: Concentric circles on a surface.
  • Sector: Smallest addressable unit (typically 512 bytes or 4KB).
$$ Capacity = \#Cylinders \times \#Heads \times \#Sectors/Track \times SectorSize $$

3. Disk Access Time

The total time to read/write data is the sum of three delays.

Component Definition Formula/Note
Seek Time (ST) Time to move the R/W head to the desired Track. Depends on hardware/distance.
Rotational Latency (RL) Time to rotate the disk so the desired Sector is under the head. $$ Avg\ RL = \frac{1}{2} \times \frac{60}{RPM} $$
Transfer Time (TT) Time to actually read/write the data. $$ TT = \frac{DataSize}{TransferRate} $$
$$ Total\ Access\ Time = Seek\ Time + Rotational\ Latency + Transfer\ Time + Overhead $$
$$ Data\ Transfer\ Rate = \#Bytes/Track \times \#Rotations/sec $$
Example Calculation: Transfer Rate

Given: 3600 RPM, Track Capacity = 4KB.

  1. Convert RPM to RPS: \(3600 / 60 = 60\) rotations per second.
  2. In 1 second, 60 tracks are passed.
  3. Rate = \(4KB \times 60 = 240 KB/sec\).

4. Disk Addressing (CHS)

Addressing scheme: < Cylinder, Head (Surface), Sector >. Addressing starts from Outer Cylinder (0), Top Surface (0), First Sector (0).

Calculate Sector Number (Linear Address) from <C, H, S>:
$$ Sector\# = S + (H \times ST) + (C \times ST \times TC) $$
Where:
\(S\): Given Sector
\(H\): Given Head/Surface
\(C\): Given Cylinder
\(ST\): Sectors per Track
\(TC\): Tracks per Cylinder (Number of Surfaces)
Why Cylinders?

Storing files cylinder-wise (vertical slice) is faster than surface-wise. It minimizes Seek Time because the head assembly doesn't need to move to switch between surfaces of the same cylinder.

5. I/O Interface Fundamentals

I/O devices (electromagnetic) are much slower than the CPU (electronic). An Interface Module is required to synchronize them.

Functions of I/O Interface

  1. Data Buffering: Smoothing out speed mismatches.
  2. Control & Timing: Coordinating traffic between CPU and external devices.
  3. Error Detection: Parity bits, peripheral status.
  4. Data Format Conversion: Serial (device) to Parallel (bus).

6. Modes of Transfer

How data moves between I/O and Memory/CPU.

Mode Mechanism CPU Involvement Use Case
Programmed I/O CPU polls device status register constantly (Busy Waiting). High (CPU is stuck waiting) Slow devices, simple systems.
Interrupt-Driven I/O Device interrupts CPU when ready. Medium (Context switching overhead) Keyboards, slow network packets.
DMA Dedicated hardware handles transfer directly to memory. Low (Only initialization) Disks, High-speed Graphics.

7. Direct Memory Access (DMA)

Allows I/O devices to access memory directly without CPU intervention. The CPU acts as the "Master" initially, then delegates control to the DMA Controller.

DMA Operation Sequence

sequenceDiagram participant CPU participant DMAC as DMA Controller participant IO as I/O Device CPU->>DMAC: Initialize (Count, Address, Control) IO->>DMAC: Request (DMA REQ) DMAC->>CPU: Hold Request (HOLD) CPU->>DMAC: Hold Acknowledge (HLDA) Note over CPU, DMAC: CPU relinquishes System Bus DMAC->>IO: DMA ACK IO->>DMAC: Data Transfer DMAC->>Memory: Write Data Note over DMAC: Until Count = 0 DMAC->>CPU: Interrupt (Finished)

DMA Transfer Modes

  • Burst Mode: DMA takes control of the bus and transfers the entire block of data before releasing it. CPU is blocked for a long duration.
  • Cycle Stealing: DMA "steals" one bus cycle to transfer one word/byte, then returns control. CPU is slowed down but not blocked indefinitely.
  • Interleaving: DMA uses the bus only when the CPU is not using it (e.g., during internal ALU operations). Transparent to CPU.
Percentage CPU Blocked:
$$ \% Blocked = \frac{TransferTime}{PreparationTime + TransferTime} \times 100 $$
