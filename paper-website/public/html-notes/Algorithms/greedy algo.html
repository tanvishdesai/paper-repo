The Greedy Method

A paradigm that builds up a solution piece by piece, always choosing the next piece that offers the most immediate benefit.

1. Introduction & Terminology

Core Concept

Greedy algorithms solve problems by making the locally optimal choice at each stage with the hope of finding a global optimum.

  • Step-wise Decision: Decisions are made one by one.
  • Irrevocable: Once a decision is made, it is not changed (unlike Backtracking).
  • Constraint Satisfaction: Must satisfy problem limits.

Key Definitions

  • Feasible Solution: A subset of inputs that satisfies all constraints (e.g., total weight $\le$ capacity).
  • Optimal Solution: A feasible solution that maximizes or minimizes the Objective Function (e.g., Max Profit).
  • Objective Function: The value we want to optimize (Profit, Cost, Distance).

2. Fractional Knapsack Problem

Given $n$ objects with weights $w_i$ and profits $p_i$, and a Knapsack capacity $M$. Maximize total profit.

$$ \text{Maximize } \sum_{i=1}^n p_i x_i \quad \text{subject to} \quad \sum_{i=1}^n w_i x_i \le M $$ $$ \text{where } 0 \le x_i \le 1 \text{ (Fraction allowed)} $$

Greedy Strategy

To maximize profit, we should prioritize items with the highest Profit-to-Weight Ratio ($P_i/W_i$).

  1. Calculate ratio $r_i = p_i / w_i$ for all items.
  2. Sort items in descending order of $r_i$.
  3. Take whole items while capacity remains.
  4. If remaining capacity < item weight, take a fraction.

Analysis

  • Time Complexity: $O(n \log n)$ (dominated by sorting).
  • 0/1 Knapsack: Greedy method fails for 0/1 Knapsack (where $x_i \in \{0,1\}$). That requires Dynamic Programming.

3. Job Sequencing with Deadlines

Given $n$ jobs, each with a Deadline $d_i$ and Profit $p_i$. Each job takes 1 unit of time. Maximize profit by completing jobs before deadlines.

Algorithm Logic

  1. Sort jobs in descending order of Profit.
  2. Find the maximum deadline $d_{max}$. Create a time slot array of size $d_{max}$.
  3. For each job, try to place it in the latest possible free slot (from $d_i$ down to 1).
  4. If a slot is found, mark it occupied and add profit.

Example

Jobs (P, D): J1(100, 2), J2(19, 1), J3(27, 2), J4(25, 1), J5(15, 3)

Sorted: J1, J3, J4, J2, J5

graph TD Slot1[Slot 1] Slot2[Slot 2] Slot3[Slot 3] J1[J1: P=100, D=2] -->|Fits| Slot2 J3[J3: P=27, D=2] -->|Slot 2 busy, try 1| Slot1 J4[J4: P=25, D=1] -->|Slot 1 busy| Reject J5[J5: P=15, D=3] -->|Fits| Slot3

Total Profit: 100 + 27 + 15 = 142

Complexity

  • Sorting: $O(n \log n)$
  • Slot Assignment: $O(n \cdot m)$ where $m$ is max deadline. Or $O(n^2)$ if $m \approx n$.
  • Optimization: Using Disjoint Set Union (DSU) to find slots reduces assignment to $O(n)$.

4. Optimal Merge Patterns & Huffman Coding

Optimal Merge Pattern

Problem: Merge $n$ sorted files with different record counts minimizing total record movements.

Strategy: Always merge the two smallest files first.

while (list.length > 1) {
    min1 = extractMin(list);
    min2 = extractMin(list);
    cost = min1 + min2;
    totalCost += cost;
    insert(list, cost);
}

Huffman Coding

Used for lossless data compression. Assigns shorter binary codes to more frequent characters.

  • Prefix Property: No code is a prefix of another (ensures unambiguous decoding).
  • Implementation: Uses a Min-Priority Queue (Min-Heap).
  • Complexity: $O(n \log n)$.

Visual Example

Combining frequencies 10 and 15 creates node 25. Then 25 combines with 30.

5. Minimum Cost Spanning Trees (MCST)

A spanning tree of a graph $G=(V,E)$ connects all vertices with minimum total edge weight and no cycles.

Properties

  • Vertices: $n$
  • Edges: $n-1$
  • Cycles: 0
  • If all weights are distinct, the MCST is unique.

Graph Representations

  • Adjacency Matrix: $O(n^2)$ space. Good for dense graphs.
  • Adjacency List: $O(n+e)$ space. Good for sparse graphs.

6. Prim's Algorithm

Strategy: Grow the tree from a starting vertex. At each step, add the cheapest edge connecting a tree vertex to a non-tree vertex.

Pseudocode


T = {start_vertex};
while (T != V) {
  find edge (u, v) with min weight
  such that u in T and v not in T;
  
  add v to T;
  add (u, v) to MST;
}

Complexity

  • Using Array/Matrix: $O(V^2)$
  • Using Binary Heap + Adj List: $O(E \log V)$
  • Using Fibonacci Heap: $O(E + V \log V)$

7. Kruskal's Algorithm

Strategy: Sort all edges by weight. Add the smallest edge to the MST if it doesn't form a cycle.

Algorithm Flow

  1. Sort edges by weight: $O(E \log E)$.
  2. Iterate through sorted edges.
  3. Use Union-Find (Disjoint Set) to check for cycles.
  4. If Find(u) != Find(v), include edge and Union(u, v).

Cycle Detection

Essential part of Kruskal's. If adding an edge connects two vertices already in the same connected component, it forms a cycle.

graph LR 1((1)) --- 2((2)) 2 --- 3((3)) 1 -.->|Cycle!| 3

Complexity: $O(E \log E)$ or $O(E \log V)$ (dominated by sorting).

8. Dijkstra's Algorithm (SSSP)

Single Source Shortest Path. Finds the shortest path from a source node to all other nodes.

Relaxation Principle

If we find a path to $v$ through $u$ that is shorter than the current known path to $v$, we update it.

$$ \text{If } d[u] + cost(u,v) < d[v] $$ $$ \text{then } d[v] = d[u] + cost(u,v) $$

Important Notes

  • Greedy Choice: Always pick the unvisited vertex with the smallest distance.
  • Limitations: Does NOT work with negative edge weights (Use Bellman-Ford).
  • Time Complexity: $O(V^2)$ (Array) or $O((V+E)\log V)$ (Min-Heap).

Special Formulas

  • Cayley's Formula: A complete graph $K_n$ has $n^{n-2}$ spanning trees.
  • Graph Edges:
    • Complete Undirected: $n(n-1)/2$
    • Complete Directed: $n(n-1)$
