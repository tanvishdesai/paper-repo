1. Lexical Analysis (Scanner)

Input: Character Stream → Output: Token Stream

Core Functions

  • Reads the program character by character.
  • Strips White Spaces and Comments.
  • Groups characters into Lexemes.
  • Generates Tokens based on patterns (RegEx).
  • Uses Maximal Munch (Longest Prefix Rule).
  • Reports Lexical Errors (e.g., invalid characters).

Terminology

  • Token: Logical unit (e.g., `id`, `number`, `keyword`).
  • Lexeme: Actual character sequence (e.g., `count`, `123`, `if`).
  • Pattern: Rule describing the token (e.g., `[a-zA-Z]+`).

Example

printf("Hello %d", x);

Tokens Generated (5): printf, (, "Hello %d", ,, x, ), ;

2. Syntax Analysis (Parser)

Input: Token Stream → Output: Parse Tree

Verifies that the sequence of tokens forms a valid sentence in the language using a Context Free Grammar (CFG).

Types of Errors Detected
  • Lexical: Spelling of keywords, illegal chars. (Detected by Scanner)
  • Syntax: Missing semicolon, unbalanced parenthesis, structure mismatch. (Detected by Parser)
  • Semantic: Type mismatch, undeclared variable, scope resolution. (Detected by Semantic Analyzer)

3. Context Free Grammar (CFG)

Defined as $G = (V, T, P, S)$.

  • $V$: Non-terminals (Variables) - Uppercase letters.
  • $T$: Terminals - Lowercase, symbols.
  • $P$: Production Rules ($LHS \to RHS$).
  • $S$: Start Symbol.

Derivation Types

Left Most Derivation (LMD)

Always replace the leftmost non-terminal first.

Used by Top-Down Parsers (LL)
Right Most Derivation (RMD)

Always replace the rightmost non-terminal first.

Reverse RMD is used by Bottom-Up Parsers (LR)

Ambiguity

A grammar is ambiguous if there exists a string $w$ such that:

  • It has > 1 Left Most Derivations.
  • It has > 1 Right Most Derivations.
  • It has > 1 Parse Trees.

Ambiguous grammars are generally bad for parsing. We convert them to unambiguous grammars.

Grammar Transformations

1. Elimination of Left Recursion

Problem: $A \to A\alpha \mid \beta$ causes infinite loops in Top-Down parsers.

Solution:

$$A \to \beta A'$$

$$A' \to \alpha A' \mid \epsilon$$

2. Left Factoring

Problem: $A \to \alpha \beta_1 \mid \alpha \beta_2$. The parser doesn't know which path to take.

Solution:

$$A \to \alpha A'$$

$$A' \to \beta_1 \mid \beta_2$$

5. Top-Down Parsing (LL)

Constructs parse tree from Root to Leaves. Uses LMD.

FIRST and FOLLOW Sets

Required to construct the parsing table.

  • FIRST($\alpha$): Set of terminals that begin strings derived from $\alpha$.
  • FOLLOW($A$): Set of terminals that can appear immediately to the right of $A$.
    Note: $ will always be in Follow(Start Symbol).

LL(1) Grammar Rules

A Grammar is LL(1) if its parsing table has no multiple entries (no conflicts).

Shortcuts to identify NOT LL(1):

  1. If G is Ambiguous → Not LL(1).
  2. If G has Left Recursion → Not LL(1).
  3. If G has Common Prefix (needs Left Factoring) → Not LL(1).

6. Bottom-Up Parsing (LR)

Constructs parse tree from Leaves to Root. Uses Reverse RMD. Known as "Shift-Reduce" parsing.

The 4 LR Parsers

Parser Item Structure Lookahead? Power Table Size
LR(0) $A \to \alpha \cdot \beta$ No Lowest Small (States)
SLR(1) $A \to \alpha \cdot \beta$ Uses Follow(A) Low Small
LALR(1) $A \to \alpha \cdot \beta, \{a\}$ Yes (Merged States) High Small
CLR(1) $A \to \alpha \cdot \beta, \{a\}$ Yes (Exact) Highest Large

Conflicts

Occur when a cell in the parse table has multiple actions.

  • SR (Shift-Reduce): Should I shift the next symbol or reduce the current handle?
  • RR (Reduce-Reduce): Multiple productions can reduce the current handle.

Conflict Resolution in Parsers

  • LR(0): Reduce is placed in entire row. Very prone to SR/RR.
  • SLR(1): Reduce $A \to \alpha$ is placed only in $Follow(A)$. Solves many LR(0) conflicts.
  • CLR(1): Uses lookaheads carried in items. Solves most conflicts.
  • LALR(1): Merges states of CLR with same core items. Can introduce RR conflicts (never SR).

7. Operator Precedence Parsing

A specialized bottom-up parser for mathematical expressions.

  • Only works for Operator Grammars (No $\epsilon$-transitions, no two adjacent non-terminals like $A \to BC$).
  • Uses Precedence Relations:
    • $\lessdot$ (Yields precedence)
    • $\doteq$ (Equal precedence)
    • $\gtrdot$ (Takes precedence)
  • Based on Associativity and Precedence of operators.
  • Parsing Logic: Scan input, find handle between $\lessdot$ and $\gtrdot$, reduce.
