Intermediate Code & Optimization

Comprehensive guide to Three Address Code, Data Flow Analysis, and Code Optimization techniques.

1. Compiler Pipeline & Overview

Intermediate Code Generation (ICG) is the bridge between the high-level front end (Analysis) and the low-level back end (Synthesis). It breaks the compiler into a Two-Pass structure.

                        C -->|Platform Independent| D[Code Optimizer]
                        D --> E[Target Code Generator]
                        E --> F[Assembly/Machine Code]

Benefits of IR

  • Retargeting: Easy to support new backends (M machines).
  • Optimization: Machine-independent optimizations are easier on IR.
  • Simplicity: Breaks the complex translation process.

2. Intermediate Representations (IR)

IR can be classified into Linear forms (sequential instructions) and Non-Linear forms (graph-based).

Linear Form: Three Address Code (3AC)

Instructions have at most 3 operands: result = operand1 op operand2.

Standard 3AC

General form with temporary variables.

x = a + b * c

t1 = b * c
x = a + t1

Static Single Assignment (SSA)

Every variable is assigned exactly once. Essential for optimization.

p = a + b
p = p * c  // Reassignment

// SSA Form:
p1 = a + b
p2 = p1 * c
Uses Φ (Phi) functions for control flow merges.

Non-Linear Form: DAG vs. Syntax Tree

Syntax Tree

Faithful representation of the grammar. Redundant sub-expressions exist.

Directed Acyclic Graph (DAG)

Eliminates common sub-expressions. Nodes with same values are reused.

  • Minimizes number of nodes/variables.
  • Used for basic block optimization.

Example: x = (a+b) * (a+b)

3. 3AC Implementation

Data structures used to store Three Address Code in memory.

Notation Structure Description Pros/Cons
Quadruples (Op, Arg1, Arg2, Result) Explicitly stores the result variable name. (+) Easy to rearrange instructions.
(-) Uses more space (symbol table size).
Triples (Op, Arg1, Arg2) Result is referred to by the index of the statement. (+) Saves space (no temp vars).
(-) Difficult to reorder code (indices change).
Indirect Triples (Op, Arg1, Arg2) + Pointer List Uses a separate list of pointers to triples. (+) Easy to reorder (swap pointers).
(-) Two memory accesses.

4. Control Flow Graph (CFG)

A representation of all paths that might be traversed through a program during execution.

Basic Blocks (BB)

A sequence of instructions with single entry (first line) and single exit (last line). No jumps in or out of the middle.

Algorithm: Finding Leaders (Start of a BB)
  1. The first statement is a leader.
  2. The target of any conditional/unconditional goto is a leader.
  3. The statement immediately following a goto/conditional goto is a leader.

Example Code

1. i = 1
2. j = 1
3. t1 = 10 * i
4. t2 = t1 + j
5. if j <= 10 goto 3
6. i = i + 1
7. if i <= 10 goto 2

Identified Basic Blocks

  • BB1 (1-2): Starts at 1 (First stmt).
  • BB2 (3-5): Starts at 3 (Target of goto in 5). Ends at 5 (Jump).
  • BB3 (6-7): Starts at 6 (Follows goto). Ends at 7.

5. Data Flow Analysis

Technique to gather information about the flow of data (values) across the CFG. Used for global optimization.

Analysis Type Direction Goal Equations (Sets)
Live Variable Backward Find variables holding values that may be used later. \( IN[B] = GEN[B] \cup (OUT[B] - KILL[B]) \)
Reaching Definitions Forward Determine which definitions of a variable may reach a point. \( OUT[B] = GEN[B] \cup (IN[B] - KILL[B]) \)

Live Variable Analysis (Liveness)

A variable x is LIVE at statement S if:

  1. There exists a statement S' that uses x.
  2. There is a path from S to S'.
  3. There is no assignment to x along the path before S'.

Calculation Steps (Backward):

  1. GEN (Use): Variables used in the block before being defined.
  2. KILL (Def): Variables defined (overwritten) in the block.
  3. OUT[B]: Union of IN sets of all successor blocks.
    \( OUT[B] = \bigcup_{S \in succ(B)} IN[S] \)
  4. IN[B]: Apply transfer function.
    \( IN[B] = GEN[B] \cup (OUT[B] - KILL[B]) \)

6. Code Optimization Techniques

Improving code efficiency (Time and Space) while preserving meaning.

Local Optimization (Basic Block Level)

Constant Folding

x = 2 * 3 + a
⬇ 
x = 6 + a

Constant Propagation

x = 10; y = x + 5
⬇ 
x = 10; y = 10 + 5

Strength Reduction

Replacing expensive ops with cheaper ones.

x = a * 2
⬇ 
x = a + a (or a << 1)

Dead Code Elimination

Removing code that is never executed or result never used.

if (0) { ... } // Removed

Loop Optimization

  • Code Motion: Moving loop-invariant code (expressions that don't change inside loop) outside.
  • Induction Variable Elimination: Removing variables that change in lock-step (e.g., i and t = 4*i).
  • Loop Unrolling: Reducing loop control overhead by replicating the body.
  • Loop Fusion: Combining two adjacent loops with same range into one.

7. Runtime Environment

How the compiler manages memory during program execution.

Static Allocation

  • Memory size known at compile time.
  • Cannot support recursion.
  • Example: Fortran 77, Global variables.

Stack Allocation

  • Memory allocated on function call (push) and deallocated on return (pop).
  • Supports Recursion.
  • Uses Activation Records.

Heap Allocation

  • Dynamic allocation (malloc/new).
  • Variables outlive the function that created them.
  • Supports dynamic data structures (Linked Lists).
