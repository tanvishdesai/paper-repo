Floating Point Representation

A comprehensive guide to understanding how computers represent real numbers using the IEEE 754 standard, including storage formats, arithmetic operations, and hardware implementation.

1. Introduction & Motivation

Why Floating Point?

Standard fixed-point 16-bit integer representations (like 2's complement) have a limited range ($ -32,768 $ to $ +32,767 $). They cannot represent:

  • Very large numbers (e.g., Avogadro's constant $ 6.022 \times 10^{23} $).
  • Very small fractions (e.g., atomic radius $ 0.5 \times 10^{-10} $).

Floating point allows the "point" to float, trading precision for a vastly larger dynamic range.

Key Concept: Floating point is essentially scientific notation in binary: $$ V = (-1)^S \times M \times 2^E $$

2. The Representation Structure

A floating point number is divided into three distinct fields:

Sign (S) 1 Bit
Biased Exponent (E) k Bits
Mantissa (M) n Bits
Field Symbol Function
Sign S 0 for Positive (+), 1 for Negative (-)
Exponent E Determines the range. Stored as Biased Exponent (no sign bit).
Mantissa M Determines the precision (significant digits).

3. Normalization & Biasing

Normalization

To ensure a unique representation for every number, we normalize the mantissa.

Explicit Normalization

Format: $ 0.1xxxx \times 2^E $

The bit after the point must be 1. It is stored explicitly.

Implicit Normalization (IEEE Standard)

Format: $ 1.xxxxx \times 2^E $

The leading '1' is implied and not stored, saving 1 bit of memory for extra precision.

Biased Exponent

We do not use 2's complement for the exponent. Instead, we use a Bias. This converts negative exponents into positive unsigned integers, making comparison of floating point numbers easier (lexicographical sort).

Formulas:
$$ E_{stored} = E_{actual} + Bias $$ $$ E_{actual} = E_{stored} - Bias $$
Bias Value (IEEE 754): $$ Bias = 2^{k-1} - 1 $$ (Where $k$ is the number of exponent bits)

Special Values Comparison

The exponents of all 0s and all 1s are reserved for special cases.

Type Exponent (E) Mantissa (M) Value Meaning
Zero 0 (All 0s) 0 (All 0s) $ \pm 0 $
Denormalized 0 (All 0s) Non-zero $ (-1)^S \times 0.M \times 2^{1-Bias} $
Normalized 1 to 254 (Max-1) Any $ (-1)^S \times 1.M \times 2^{E-Bias} $
Infinity 255 (All 1s) 0 (All 0s) $ \pm \infty $ (Overflow/Div by 0)
NaN 255 (All 1s) Non-zero Not a Number (e.g., $\sqrt{-1}$)
Example: Converting Decimal 13.5 to IEEE 754 (Single)
  1. Convert to Binary: $ 13.5_{10} = 1101.1_2 $
  2. Normalize: Shift decimal left by 3: $ 1.1011 \times 2^3 $
  3. Identify Components:
    • Sign: Positive $\rightarrow 0$
    • Mantissa (stored): 1011000... (drop leading 1, pad to 23 bits)
    • Actual Exponent: 3
  4. Calculate Biased Exponent: $ E = 3 + 127 = 130 $
    Binary of 130: $ 10000010_2 $
  5. Assemble:
    0 10000010 10110000000000000000000
  6. Hex: $ 41580000_{16} $

5. Floating Point Arithmetic

Floating point math is complex because the binary points must be aligned before addition/subtraction, and results must be renormalized.

Addition / Subtraction Algorithm

graph TD A[Start] --> B[Check for Zeros] B --> C[Compare Exponents] C --> D[Shift Mantissa of Smaller Number Right] D --> E{Exponents Equal?} E -- No --> D E -- Yes --> F[Add/Sub Mantissas] F --> G[Normalize Result] G --> H[Check Overflow/Underflow] H --> I[Round Result] I --> J[End]

Multiplication Rules

  1. Add Exponents: $ E_{new} = E_1 + E_2 - Bias $ (Subtract bias once because it's added twice).
  2. Multiply Mantissas: $ 1.M_1 \times 1.M_2 $.
  3. Normalize: Shift result if necessary and adjust exponent.
  4. Sign: XOR the sign bits ($ S_{result} = S_1 \oplus S_2 $).
