1. Binary Heaps

A Heap is a complete binary tree where the value at each node satisfies a specific order property relative to its children.

Properties

  • Structure: Complete Binary Tree (filled level-by-level, left-to-right).
  • Max-Heap: $A[parent] \ge A[child]$. Root is the maximum.
  • Min-Heap: $A[parent] \le A[child]$. Root is the minimum.
  • NOT a BST: No relationship between left and right siblings.

Array Representation

For a node at index $i$ (1-based indexing):

  • Left Child: $2i$
  • Right Child: $2i + 1$
  • Parent: $\lfloor i/2 \rfloor$

2. Operations

Insertion

  1. Insert element at the next available leaf position (end of array).
  2. Compare with parent. If order is violated, swap.
  3. Repeat upwards until property is restored.
Time Complexity: $O(\log n)$ (Height of tree)

Deletion (Extract Max)

  1. Remove root (max element).
  2. Move the last element (leaf) to the root.
  3. Perform Adjust (Heapify Down) to fix property.
Time Complexity: $O(\log n)$

Algorithm: Heapify (Adjust)

Used to fix a heap violation at node $i$ assuming subtrees are already heaps.

procedure ADJUST(A, i, n)
    item = A[i]; j = 2*i;
    while(j <= n) {
        // Point to larger child
        if (j < n and A[j] < A[j+1]) j = j+1;
        
        if (item >= A[j]) break; // Position found
        
        A[j/2] = A[j]; // Move child up
        j = 2*j;
    }
    A[j/2] = item;
end

3. Construction (Build Heap)

Converting an arbitrary array into a Max-Heap.

Method 1: Repeated Insertion

Start with empty heap, insert elements one by one.

Worst Case: Input is sorted ascending.

$O(n \log n)$

Method 2: Heapify (Bottom-Up)

Treat array as complete tree. Call ADJUST starting from the last internal node down to the root.

$T(n) = \sum_{i=\lfloor n/2 \rfloor}^{1} \text{Adjust}(i)$
Optimized: $O(n)$
Why is Bottom-Up Build Heap O(n)? (Click to Expand)

The cost depends on the height $h$ of the node. There are fewer nodes at greater heights.
$$ T(n) = \sum_{h=0}^{\log n} \lceil \frac{n}{2^{h+1}} \rceil O(h) $$ Using the summation series $\sum_{i=0}^{\infty} \frac{i}{2^i} = 2$: $$ T(n) \le n \sum_{i=0}^{\infty} \frac{i}{2^i} = n(2) = O(n) $$
Intuition: Most nodes are leaves (height 0) and take 0 time. Only the root takes $\log n$ time.

4. Heap Sort

Procedure

  1. Build Max Heap: Convert input array. $O(n)$
  2. Extract Max $n-1$ times:
    • Swap Root with last element.
    • Reduce heap size by 1.
    • Heapify root.
    $(n-1) \times \log n$

Complexity Analysis

  • Total Time: $O(n \log n)$
  • Space: $O(1)$ (In-place)
  • Stability: Unstable

5. Optimal Binary Search Tree (OBST)

Constructing a BST to minimize the expected search cost given probabilities for keys (successful) and intervals between keys (unsuccessful).

The Cost Function

Given identifiers $(a_1, \dots, a_n)$ with probabilities $(p_1, \dots, p_n)$ and dummy/failure nodes $(E_0, \dots, E_n)$ with probabilities $(q_0, \dots, q_n)$.

$$ Cost(T) = \sum_{i=1}^{n} p_i \cdot level(a_i) + \sum_{i=0}^{n} q_i \cdot (level(E_i) - 1) $$

Note: Root is at level 1.

Dynamic Programming Solution

Let $C(i, j)$ be the cost of the optimal BST containing keys $a_{i+1} \dots a_j$.

$$ C(i, j) = \min_{i < k \le j} \{ C(i, k-1) + C(k, j) \} + w(i, j) $$
  • $w(i, j)$: Sum of all $p$ and $q$ probabilities in the range.
  • Base Case: $C(i, i) = 0$ (Empty tree, just dummy node cost usually handled via init).
  • Time Complexity: $O(n^3)$
  • Number of possible BSTs: Catalan Number $\frac{1}{n+1}{2n \choose n}$.

6. Solving Recurrences

Recursion Tree Method

Visualize the work done at each level of the recursion.

graph TD Root[n] --> L[n/2] Root --> R[n/2] L --> LL[n/4] L --> LR[n/4] R --> RL[n/4] R --> RR[n/4] style Root fill:#fff,stroke:#333

Example: $T(n) = 2T(n/2) + n$

  • Level 0 cost: $n$
  • Level 1 cost: $n/2 + n/2 = n$
  • Level 2 cost: $4 \times (n/4) = n$
  • Total: $n \times (\text{Height}) = n \log n$

Common Patterns (Master Theorem Scope)

Recurrence Complexity Remark
$T(n) = 2T(n/2) + n$ $O(n \log n)$ Merge Sort
$T(n) = T(n/2) + 1$ $O(\log n)$ Binary Search
$T(n) = 2T(n/2) + 1$ $O(n)$ Traversals
$T(n) = T(n-1) + 1$ $O(n)$ Linear Scan
$T(n) = 3T(n/4) + n^2$ $O(n^2)$ Root dominates

7. Disjoint Set Data Structure

Used to manage partition of a set into disjoint subsets. Supports Union and Find.

Array Representation

Assume elements $1 \dots n$. Array $P[1 \dots n]$ stores the parent of $i$.

  • If $P[i] < 0$ (or specific value like -1), $i$ is a root. Magnitude can store size/rank.
  • If $P[i] > 0$, $P[i]$ is the index of the parent.
Index (i) 1 2 3 4
Parent (P) -1 1 -1 3

Represents sets $\{1, 2\}$ (1 is root) and $\{3, 4\}$ (3 is root).

Operations

Find(i):
    while(P[i] >= 0) i = P[i];
    return i;
    // Time: O(n) (skewed tree)

Union(i, j):
    P[i] = j; // Make j parent of i
    // Time: O(1)

Application: Kruskal's Algorithm

Used to find Minimum Spanning Tree (MST).

  1. Sort edges by weight (or build Min-Heap).
  2. Iterate through edges $(u, v)$.
  3. If Find(u) != Find(v), add edge and Union(u, v).
Time: $O(E \log E)$ or $O(E \log V)$
