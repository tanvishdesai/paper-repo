Syntax Directed Translation (SDT)

A comprehensive guide to attaching semantics to syntax in compiler design. Based on CS & IT Engineering Lecture Notes.

1. Overview

Syntax Directed Translation is a generalization of a Context-Free Grammar (CFG) in which each grammar symbol has an associated set of attributes, and each production rule is associated with a set of semantic rules (translation actions).

SDT = CFG + Semantic Rules

Why use SDT?

  • Generates Intermediate Code
  • Performs Type Checking (Semantic Analysis)
  • Generates Parse Trees
  • Translates expressions (Infix \(\to\) Postfix)
  • Evaluates expressions (Calculator)

Lexical vs Syntax vs Semantic

  • Lexical: Tokens (Is "if" a keyword?)
  • Syntax: Structure (Do parentheses match?)
  • Semantic: Meaning (Is variable declared before use? Type mismatch?)
  • SDT: Powerhouse for checking Semantics.

2. Types of Attributes

Attributes store information (values, types, locations) associated with grammar symbols. The flow of data in the parse tree depends on the attribute type.

Synthesized Attribute

The value of the attribute at a node is computed from the values of its children.

E → E₁ + E₂  { E.val = E₁.val + E₂.val }

Direction: Bottom-Up

mermaid graph BT C1[Child 1] --> P[Parent] C2[Child 2] --> P style P stroke:#38bdf8,stroke-width:2px

Inherited Attribute

The value at a node is computed from the values of its parent and/or siblings.

A → B C  { C.in = A.in + B.val }

Direction: Top-Down or Sideways

mermaid graph TD P[Parent] --> C2[Child 2 (Target)] C1[Sibling] --> C2 style C2 stroke:#fbbf24,stroke-width:2px

3. SDT Definitions (S vs L)

Classifying SDTs helps determine how efficiently they can be evaluated during parsing.

Feature S-Attributed SDT S-Att L-Attributed SDT L-Att
Allowed Attributes Synthesized Attributes ONLY. Synthesized attributes + Restricted Inherited attributes.
Dependency Attribute of LHS depends only on RHS attributes (Children). Attribute of a symbol on RHS can depend on:
1. Parent
2. Left Siblings
3. Own attributes
Never Right Siblings!
Action Placement Semantic actions placed at the end of production. Semantic actions can be placed anywhere in production.
Evaluation Bottom-Up Parsing (Post-order traversal). Depth First Search (Left-to-Right traversal).
Example Rule \(S \to A B \{ S.x = A.y + B.z \}\) \(S \to A \{ A.i = S.i \} B\)

Dependency Restriction for L-Attributed

In a production \(A \to X_1 X_2 \dots X_n\):

The inherited attributes of \(X_i\) can only depend on:

  1. Inherited attributes of \(A\) (Parent).
  2. Attributes of \(X_1, \dots, X_{i-1}\) (Left Siblings).

Example of Violation (Not L-Attributed): \(A \to B C \{ B.x = C.y \}\)

Why? \(B\) is trying to get data from \(C\), which is its right sibling. The parser hasn't seen \(C\) yet when processing \(B\).

4. Evaluation & Annotated Parse Trees

An Annotated Parse Tree is a parse tree showing the values of attributes at each node.

Evaluation Orders

  • Topological Sort: Works for any non-circular dependency graph.
  • S-Attributed: Evaluated using Post-Order Traversal (perfect for LR Parsers/Bottom-Up). Corresponds to Reverse Rightmost Derivation.
  • L-Attributed: Evaluated using DFS (Left-to-Right). Can be done during Top-Down parsing (LL) or using a hybrid stack.

Example: Calculating 10 # 3 (where # is summation)

Grammar:

S → A # B  { S.val = A.val + B.val }
A → num    { A.val = num.lexval }
B → num    { B.val = num.lexval }

Input: 10 # 3

Process:

  1. Reduce 10 to A (A.val = 10)
  2. Reduce 3 to B (B.val = 3)
  3. Reduce A # B to S (S.val = 10 + 3 = 13)

5. Applications & Practice Patterns

Pattern 1: Counting Parentheses / Length

Problem: Count number of balanced parentheses pairs.

S → ( S₁ )  { S.count = S₁.count + 1 }
S → S₁ S₂   { S.count = S₁.count + S₂.count }
S → ε       { S.count = 0 }

Functionality: Counts nesting depth or total matched pairs. If counting terminals, change the +1 logic.

Pattern 2: Binary to Decimal

Input: 101 (Binary)

L → L₁ B   { L.val = L₁.val * 2 + B.val }
L → B      { L.val = B.val }
B → 0      { B.val = 0 }
B → 1      { B.val = 1 }

Type: Synthesized (S-Attributed).

Pattern 3: Infix to Postfix (Printing)

Input: 9 + 5

E → E + T  { print('+') }
E → T
T → num    { print(num.val) }

Traveral (9+5):

  1. Process 9 (Print '9')
  2. Process 5 (Print '5')
  3. Reduce E+T (Print '+')

Output: 9 5 +

Note: Often used in Bottom-Up parsing.

Pattern 4: Type Checking

Used to verify if operands match types.

E → E₁ + E₂  
{ 
  if (E₁.type == int && E₂.type == int) E.type = int;
  else if (E₁.type == float && E₂.type == float) E.type = float;
  else error();
}
