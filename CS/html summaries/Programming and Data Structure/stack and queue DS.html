1. Stack Fundamentals

Concept

A Linear Data Structure that follows the LIFO (Last In First Out) principle. The element inserted last is the first one to be deleted.

Analogy: A stack of plates or coins.

Key Pointer: TOP

  • TOP stores the index of the most recently added element.
  • Insertion/Deletion only happens at the TOP end.
graph TD subgraph Stack Visual direction BT C[Data 3 (TOP)] B[Data 2] A[Data 1] end Action[Push/Pop] --> C

Operations & Complexity

Operation Description Condition Check Time Complexity
Push(x) Insert element x Check Overflow: TOP == SIZE - 1 O(1)
Pop() Remove top element Check Underflow: TOP == -1 O(1)
Peek() View top element Check TOP == -1 O(1)
Implementation Code (C-Style) 
#define SIZE 10
int STACK[SIZE];
int TOP = -1;

void Push(int x) {
    if (TOP == SIZE - 1) {
        printf("Overflow"); 
        return;
    }
    STACK[++TOP] = x;  // Increment then Insert
}

int Pop() {
    if (TOP == -1) {
        printf("Underflow"); 
        return INT_MIN;
    }
    return STACK[TOP--]; // Return then Decrement
}

2. Stack Permutations & Catalan Numbers

If the input sequence is $(1, 2, 3, \dots, n)$ (pushed in increasing order), the number of valid output permutations achievable using a stack is given by the Catalan Number.

$$ C_n = \frac{1}{n+1} \binom{2n}{n} = \frac{(2n)!}{(n+1)!n!} $$

Examples

  • n = 3: Input (1, 2, 3). Total Permutations = $3! = 6$. Valid Stack Permutations = $5$.
  • Invalid Sequence: 3, 1, 2 (Because if 3 is popped first, 1 and 2 are in stack. 2 is above 1, so 2 must be popped before 1).

Rule of Thumb

"For a sequence to be impossible, there must exist indices i < j < k such that output[k] < output[i] < output[j]."

Simpler check: If you pop a large number $X$, all numbers smaller than $X$ that haven't appeared yet must appear in descending order.

3. Expression Handling

One of the primary applications of Stacks is parsing arithmetic expressions.

Infix

A + B

Operator between operands. Human readable.

Prefix (Polish)

+ A B

Operator before operands. Parsed Right to Left.

Postfix (Reverse Polish)

A B +

Operator after operands. Parsed Left to Right. Used by Compilers.

Infix to Postfix Conversion Algorithm

Goal: Respect Precedence (BODMAS rules adapted) and Associativity.

flowchart LR Start(Scan Symbol) --> Check{Type?} Check -- Operand --> Output[Print to Output] Check -- "(" --> PushStack[Push to Stack] Check -- ")" --> PopUntil[Pop to Output until '('] Check -- Operator --> Compare{Precedence?} Compare -- Higher than Top --> PushStack Compare -- Lower/Equal --> PopStack[Pop Top to Output] --> Compare
Example Trace: A + B * C

Applications

  • Balanced Parentheses Checking: Push for opening ( { [, Pop for matching closing ) } ]. Stack must be empty at end.
  • Expression Evaluation: To evaluate Postfix, push operands. When operator found, pop two, calculate, push result.

4. Queue Fundamentals

Concept

A Linear Data Structure following FIFO (First In First Out).

Analogy: A line of people at a ticket counter.

  • Rear: Insertion end (Enqueue).
  • Front: Deletion end (Dequeue).
graph LR Input(Enqueue) --> Rear subgraph Queue A[10] --- B[20] --- C[30] end Front --> Output(Dequeue)

The "False Overflow" Problem

In a linear array implementation, if we delete elements, Front moves forward. Even if empty spaces exist at the beginning (indices 0, 1...), we cannot insert new elements if Rear has reached SIZE-1. This is memory wastage.

Solution: Circular Queue.

5. Circular Queue

We treat the array as a loop. Next position after SIZE-1 is 0.

Logic Formulas

  • Next Position: (Index + 1) % SIZE
  • Full Condition: (Rear + 1) % SIZE == Front
  • Empty Condition: Front == -1

Operations

Enqueue(x): Move Rear circularly, then insert.

Dequeue(): Store Front element, move Front circularly.

Circular Queue Code Snippet 
void CQ_Enqueue(int x) {
    if ((Rear + 1) % SIZE == Front) {
        printf("Overflow");
        return;
    }
    if (Front == -1) Front = Rear = 0; // First element
    else Rear = (Rear + 1) % SIZE;
    
    Queue[Rear] = x;
}

6. Data Structure Interconversion

Common interview questions involving implementing one structure using another.

Queue using Stacks

graph LR Input --> S1[Stack 1: Input] S1 -- Transfer Logic --> S2[Stack 2: Output] S2 --> Output
Method Enqueue Cost Dequeue Cost Logic
Make Enqueue Costly O(N) O(1) Move all S1 to S2, push x to S1, move back S2 to S1.
Make Dequeue Costly O(1) O(N) (Amortized O(1)) Push to S1. To pop: if S2 empty, move all S1 to S2, then pop S2.

Stack using Queues

  • Requires 2 Queues ($Q_1, Q_2$).
  • Push Costly: Enqueue to $Q_2$, move all $Q_1$ to $Q_2$, swap names. Cost: $O(N)$.
  • Pop Costly: Leave one element in $Q_1$ by moving $N-1$ elements to $Q_2$. Cost: $O(N)$.

7. Priority Queue

A queue where each element has a priority. Elements are processed based on priority, not just arrival time.

Representation

Can be implemented using:

  1. Array/Linked List: Simple but slow ($O(N)$ insertion or deletion).
  2. Heap (Binary Heap): Efficient ($O(\log N)$ for both).

Types

  • Ascending PQ: Smallest number = Highest Priority.
  • Descending PQ: Largest number = Highest Priority.

Applications: CPU Scheduling (Process management), Dijkstra's Shortest Path Algorithm.
