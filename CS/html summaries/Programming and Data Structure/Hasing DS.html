Hashing & Data Structures

Chapter 07 • CS & IT Engineering • Based on Lectures 01 & 02 by Pankaj Sharma Sir

1. Introduction to Hashing

Hashing is a technique used to uniquely identify a specific object from a group of similar objects. It is designed to solve the problem of finding data in constant time.

Why Hashing?

Comparing Search Complexities for \(n\) elements:

  • Array/Linked List: \(O(n)\) (Linear Search)
  • BST / Balanced Tree (AVL): \(O(\log n)\)
  • Hashing: \(O(1)\) Ideal

The Challenge

If we have a universe of keys \(U\) (e.g., \(2^{20} \approx 10^6\)), creating a Direct Address Table of size \(2^{20}\) is memory inefficient if we only store 50 items.

2. The Hash Function

A function \(h(k)\) that maps a large key \(k\) to a small integer index in the range \([0, m-1]\), where \(m\) is the table size.

\[ h(k) = k \mod m \]

Properties of a Good Hash Function

  1. Efficient: Easy and fast to compute.
  2. Uniform Distribution: It should distribute keys uniformly across the table to minimize collisions.

Example

Let \(m = 10\). Keys: 12, 11, 18.

  • \(h(12) = 12 \mod 10 = 2\)
  • \(h(11) = 11 \mod 10 = 1\)
  • \(h(18) = 18 \mod 10 = 8\)

3. Collision Resolution Techniques (CRT)

A Collision occurs when two distinct keys map to the same index: \(h(k_1) = h(k_2)\). Since we cannot store two values in one slot, we need a resolution strategy.

4. Linear Probing (Open Addressing)

If the calculated hash slot is occupied, check the next slot linearly until an empty one is found.

\[ H(k, i) = (h(k) + i) \mod m \]

Where \(i = 0, 1, 2, \dots\) is the probe number.

Example Walkthrough

Table Size \(m=10\), Hash \(h(k) = k \mod 10\)

  • Insert 4: \(h(4)=4\). Slot 4 empty. Insert
  • Insert 14: \(h(14)=4\). Collision. Try \(i=1\): \((4+1)\%10 = 5\). Empty. Insert
  • Insert 24: \(h(24)=4\). Collision. Try \(i=1 \to 5\) (Occupied). Try \(i=2 \to 6\). Empty. Insert

Problem: Primary Clustering

Long runs of occupied slots build up, increasing the average search time. Any key that hashes into a cluster will lengthen it.

Deletion Issue

Deletion is tricky. If we simply remove 26 from a cluster, searching for a subsequent element (e.g., 14) might fail because the search stops at the empty slot.
Solution: We must Re-hash remaining keys in the cluster after a deletion.

5. Quadratic Probing

To reduce primary clustering, we look for slots at quadratic intervals ($1^2, 2^2, 3^2 \dots$) rather than linear ($1, 2, 3 \dots$).

\[ H(k, i) = (h(k) + i^2) \mod m \]

Mechanism

If \(h(k) = L\) is full:

  • \(i=1\): Check \((L + 1^2) \mod m\)
  • \(i=2\): Check \((L + 2^2) \mod m\)
  • \(i=3\): Check \((L + 3^2) \mod m\)

Problem: Secondary Clustering

Although it solves primary clustering, keys hashing to the same initial position will follow the exact same probe sequence.

Example: If \(h(k_1) = h(k_2)\), both will try \(L+1\), then \(L+4\), then \(L+9\)...

Example Constraint (Slide Data): \(m=11\).
Keys: 24, 17, 32, 2, 13, 50, 30, 61.
Even with 50% free slots, specific probe sequences might fail to find an empty spot if the table size and probe step aren't co-prime or carefully chosen.

6. Double Hashing

Uses a second hash function to calculate the probe step size. This eliminates secondary clustering because the step size depends on the key itself.

\[ H(k, i) = (h_1(k) + i \cdot h_2(k)) \mod m \]

The Functions

  • Primary: \(h_1(k) = k \mod m\)
  • Secondary: \(h_2(k) = C - (k \mod C)\) (typically)
CRITICAL RULE:

\(h_2(k)\) must never evaluate to 0. If it does, \(i \cdot 0 = 0\), and the algorithm loops on the same index infinitely.

Example Walkthrough

\(m=11\). Let \(h_1(k) = k \mod 11\) and \(h_2(k) = 7 - (k \mod 7)\).

Insert 30:

  1. \(h_1(30) = 8\) (Assume occupied)
  2. Calculate Step: \(h_2(30) = 7 - (30 \mod 7) = 7 - 2 = 5\)
  3. Probe 1: \((8 + 1 \cdot 5) \mod 11 = 13 \mod 11 = 2\)
  4. Probe 2: \((8 + 2 \cdot 5) \mod 11 = 18 \mod 11 = 7\)

7. Separate Chaining (Closed Addressing)

Instead of finding a new slot, each slot in the table contains a pointer to a linked list (or chain). All colliding keys are appended to this list.

graph LR Slot0[0] --> Null1[NULL] Slot1[1] --> NodeA[400] --> NodeB[500] --> Null2[NULL] Slot2[2] --> Null3[NULL] Slot5[5] --> NodeC[635] --> NodeD[425] --> Null4[NULL]

Load Factor (\(\lambda\))

\[ \lambda = \frac{n}{m} \]
  • \(n\): Number of keys
  • \(m\): Table size

If \(\lambda > 1\), it means there are more keys than slots. Separate Chaining handles this gracefully, while Open Addressing fails (requires resizing).

8. Summary & Comparison

Technique Formula Pros Cons
Linear Probing \((h(k)+i)\%m\) Easy to implement, cache friendly. Primary Clustering
Quad. Probing \((h(k)+i^2)\%m\) Avoids primary clustering. Secondary Clustering
Double Hashing \((h_1(k) + i \cdot h_2(k))\%m\) Uniform distribution, no clustering. Computationally expensive (2 hashes).
Sep. Chaining Linked Lists Handles \(\lambda > 1\), simple deletion. Extra memory (pointers), cache unfriendly.

Conclusion

  • Use Open Addressing when key size is known and \(\lambda \le 1\).
  • Use Separate Chaining when deletions are frequent or number of keys is unknown (\(\lambda > 1\)).
