1. Functional Dependencies (FD)

The fundamental constraints that determine the relationship between attributes in a relation.

DEF Functional Dependency

Let \( R \) be a relation schema. An FD \( X \rightarrow Y \) holds if for every valid instance of \( R \), whenever two tuples agree on \( X \), they must also agree on \( Y \).

If \( t_1.X = t_2.X \) then \( t_1.Y = t_2.Y \)

Types of FDs

  • Trivial FD \( X \rightarrow Y \) is trivial if \( Y \subseteq X \). Always valid.
    Example: AB → A
  • Non-Trivial \( X \rightarrow Y \) where \( X \cap Y = \emptyset \).
    Example: A → B
  • Semi-Non-Trivial \( X \rightarrow Y \) where \( X \cap Y \neq \emptyset \) but \( Y \not\subseteq X \).
    Example: AB → BC

2. Armstrong's Axioms

Rule Name Logic Description
Reflexivity If \( Y \subseteq X \), then \( X \rightarrow Y \) Trivial dependency rule.
Augmentation If \( X \rightarrow Y \), then \( XZ \rightarrow YZ \) Adding attributes to both sides.
Transitivity If \( X \rightarrow Y \) and \( Y \rightarrow Z \), then \( X \rightarrow Z \) Chain rule.
Union If \( X \rightarrow Y \) and \( X \rightarrow Z \), then \( X \rightarrow YZ \) Derived rule.
Decomposition If \( X \rightarrow YZ \), then \( X \rightarrow Y \) and \( X \rightarrow Z \) Derived rule.
Pseudo-transitivity If \( X \rightarrow Y \) and \( WY \rightarrow Z \), then \( WX \rightarrow Z \) Derived rule.

3. Attribute Closure & Keys

Attribute Closure \( [X]^+ \)

The set of all attributes that can be functionally determined by \( X \) using the given set of FDs.

Algorithm: Start with \( X \). If \( A \rightarrow B \) exists and \( A \) is in the set, add \( B \) to the set. Repeat until no changes.

Types of Keys

  • Super Key (SK): Closure determines ALL attributes.
  • Candidate Key (CK): Minimal Super Key (No proper subset is a SK).
  • Primary Key (PK): One selected CK.
  • Prime Attribute: Part of ANY Candidate Key.
  • Non-Prime Attribute: Not part of ANY Candidate Key.

4. Minimal Cover (Canonical Cover)

A simplified set of FDs equivalent to the original set, stripped of redundancies.

Step 1
Singleton RHS
Split \( A \rightarrow BC \) into \( A \rightarrow B \) and \( A \rightarrow C \).
Step 2
Remove Extraneous LHS
If \( AB \rightarrow C \) and \( A \rightarrow C \), then \( B \) is extraneous in the first FD. Check closures!
Step 3
Remove Redundant FDs
If an FD can be derived from the others, delete it.

5. Decomposition Properties

Lossless Join

Ensures no spurious tuples are generated when joining decomposed tables.

Condition for \( R_1, R_2 \):
\( R_1 \cap R_2 \) must be a Super Key of either \( R_1 \) or \( R_2 \).
(R1 ∩ R2) → R1 OR (R1 ∩ R2) → R2

Dependency Preservation

Ensures all original FDs can be checked within the individual decomposed tables without joining.

Condition:
\( (F_1 \cup F_2 \cup \dots \cup F_n)^+ \equiv F^+ \)
It's okay if transitive dependencies are lost across tables, but constraints must hold.

7. Decomposition Strategies

3NF Decomposition Algorithm (Bernstein's Synthesis) ▼

Goal: Lossless Join + Dependency Preservation.

  1. Find the Minimal Cover of \( F \).
  2. For each FD \( X \rightarrow Y \) in minimal cover, create a table \( R_i(X, Y) \).
  3. If attributes in a Candidate Key are not yet in any table, create a table containing the Candidate Key.
  4. (Optional) Merge tables where one table's relation is a subset of another.
BCNF Decomposition Algorithm ▼

Goal: Lossless Join (Dependency Preservation NOT guaranteed).

graph TD Start[Check if R is in BCNF] Check{Violation X -> Y?} Yes[Decompose R] --> Sub1[R1 = X U Y] Yes --> Sub2[R2 = R - Y] Sub1 --> Recurse1[Recursive Check] Sub2 --> Recurse2[Recursive Check] No[Stop] Start --> Check Check -->|Yes| Yes Check -->|No| No

1. Identify a violation \( X \rightarrow Y \) where \( X \) is not a Super Key.

2. Decompose \( R \) into \( R_1(X \cup Y) \) and \( R_2(Attributes(R) - Y) \).

3. Repeat for resulting tables until all are BCNF.
