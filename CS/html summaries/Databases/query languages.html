Query Languages

A comprehensive synthesis of Relational Algebra (Procedural) and SQL (Declarative). Understanding the mathematical foundation and practical implementation of database queries.

Two Sides of the Coin

Relational Algebra (RA)

Procedural: Specifies how to get the data.

Theoretical foundation. Operations on sets/relations.

SQL

Declarative: Specifies what data is needed.

Practical implementation. Works on Multisets (Bags).

Relational Algebra Operators

Operators take one or two relations as input and produce a new relation as output.

Selection (\(\sigma\))

Horizontal Filtering. Selects rows satisfying a condition.

$$ \sigma_{condition}(R) $$

Example: \(\sigma_{age>18}(Student)\)

Projection (\(\pi\))

Vertical Filtering. Selects specific columns. Removes duplicates in RA (Set Theory).

$$ \pi_{col1, col2}(R) $$

Example: \(\pi_{name}(Student)\)

Cross Product (\(\times\))

Combines every row of R with every row of S.

Degree: \(Deg(R) + Deg(S)\)

Cardinality: \(|R| \times |S|\)

Deep Dive: Set Operations Requirements

For Union (\(\cup\)), Intersection (\(\cap\)), and Difference (-), relations must be Union Compatible:

  1. Same Arity (Number of attributes).
  2. Corresponding attributes must have the same domain (data type).
Note: Intersection can be derived: \(R \cap S = R - (R - S)\).

Joins & Connections

Joins reconstruct information from decomposed tables. They are essentially a Cross Product followed by a Selection.

Join Type Symbol Description Handling Mismatches
Natural Join \(R \bowtie S\) Equi-join on common attributes. Removes duplicate columns. Discards mismatched rows (Dangling Tuples).
Theta Join \(R \bowtie_{\theta} S\) Join based on arbitrary condition \(\theta\) (e.g., \(>\), \(<\)). Discards mismatches.
Left Outer \(R \_ \bowtie S\) Preserves all tuples from Left table. Pads with NULL for right table.
Right Outer \(R \bowtie\_ S\) Preserves all tuples from Right table. Pads with NULL for left table.

The Division Operator (/)

Used for queries involving "for all" or "every". (e.g., "Find students enrolled in ALL courses").

Formula Derivation

$$ R(A, B) \div S(B) $$

Result is a relation with attributes \(A\).

Logic:

  1. Find all potential candidates: \(\pi_A(R)\).
  2. Find candidates that are missing at least one mapping to S: $$ \pi_A ( (\pi_A(R) \times S) - R ) $$
  3. Subtract the "bad" candidates from all candidates: $$ \pi_A(R) - \pi_A ( (\pi_A(R) \times S) - R ) $$

SQL Anatomy & Execution Order

SQL is declarative. You write in a specific order, but the engine executes in a logical order.

graph TD subgraph "Lexical Order (How you write)" L1[SELECT] --> L2[FROM] L2 --> L3[WHERE] L3 --> L4[GROUP BY] L4 --> L5[HAVING] L5 --> L6[ORDER BY] end subgraph "Logical Execution Order (How it runs)" E1[FROM / JOIN] -->|Cartesian Product| E2[WHERE] E2 -->|Filter Rows| E3[GROUP BY] E3 -->|Create Groups| E4[HAVING] E4 -->|Filter Groups| E5[SELECT] E5 -->|Project Columns| E6[DISTINCT] E6 -->|Remove Duplicates| E7[ORDER BY] end L1 -.-> E5 L2 -.-> E1 L3 -.-> E2 
-- Typical Structure
SELECT DISTINCT S.Name, AVG(M.Score)
FROM Students S 
JOIN Marks M ON S.ID = M.StudentID
WHERE S.City = 'New York'
GROUP BY S.Name
HAVING AVG(M.Score) > 80
ORDER BY S.Name ASC;

Aggregation & Grouping

Aggregates (`COUNT`, `SUM`, `AVG`, `MIN`, `MAX`) take a collection of values and return a single value.

WHERE vs. HAVING

  • WHERE: Filters individual rows. Cannot use aggregates (e.g., `WHERE sum(x) > 5` is Illegal).
  • HAVING: Filters groups. Applied after `GROUP BY`. Can use aggregates.

GROUP BY Rule

If `GROUP BY` is used, the `SELECT` clause can only contain:

  1. Attributes listed in `GROUP BY`.
  2. Aggregate functions.

The NULL Trap

NULL is not zero. NULL is not empty string. NULL is Unknown or Non-existent.

Critical Behaviors

  • Arithmetic: `5 + NULL = NULL`
  • Comparison: `5 > NULL` is UNKNOWN (treated as False in WHERE).
  • Equality: `NULL = NULL` is UNKNOWN. Use `IS NULL` or `IS NOT NULL`.
  • Aggregation: `SUM`, `AVG`, `MIN`, `MAX` ignore NULLs.
  • COUNT: `COUNT(*)` counts rows (including NULLs). `COUNT(column)` ignores NULLs.

Nested Queries (Subqueries)

Independent Subquery

Inner query runs once. Result passed to outer query.

Execution: Bottom-up.

SELECT * FROM R 
WHERE R.id IN (SELECT id FROM S)

Correlated Subquery

Inner query relies on a value from the outer query row.

Execution: Top-down (Nested Loop). For every row in Outer, execute Inner.

SELECT * FROM Emp E1
WHERE salary > (SELECT AVG(salary) 
                FROM Emp E2 
                WHERE E2.Dept = E1.Dept)

Special Operators

  • ANY: Logical OR. `x > ANY(10, 20)` means `x > 10` OR `x > 20`.
  • ALL: Logical AND. `x > ALL(10, 20)` means `x > 10` AND `x > 20`.
  • EXISTS: Returns TRUE if the subquery returns at least one row.
