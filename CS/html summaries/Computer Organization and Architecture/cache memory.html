1. Memory Hierarchy & Locality

The Hierarchy

The system organizes memory into levels to minimize access time while balancing cost and capacity. The CPU always looks at the fastest memory first.

Goal: Simulate the speed of the fastest memory with the size of the largest memory.
graph TD A[CPU Registers] --> B[Cache Memory] B --> C[Main Memory] C --> D[Secondary Memory] style A fill:#ffcccc,stroke:#333 style B fill:#ffe5cc,stroke:#333 style C fill:#ffffcc,stroke:#333 style D fill:#e5ffcc,stroke:#333
Locality of Reference

Cache works because programs do not access memory randomly. They exhibit predictable patterns.


  • Temporal Locality: If a word is referenced, it (or its neighbors) will likely be referenced again soon (e.g., Loops, Variables).
  • Spatial Locality: If a word is referenced, adjacent words will likely be referenced soon (e.g., Arrays, Sequential Code).
Note: When a Cache Miss occurs, we bring an entire BLOCK (not just one word) from Main Memory to satisfy Spatial Locality.

2. Average Memory Access Time (AMAT)

Performance is inversely proportional to Execution Time. We measure memory performance via AMAT ($T_{avg}$).

Simultaneous Access

CPU sends requests to L1 and Lower Levels in parallel.

$$ T_{avg} = H \cdot T_c + (1-H) \cdot T_m $$

Hierarchical Access

CPU checks L1 first. If miss, goes to L2/MM, then brings data to L1, then to CPU.

$$ T_{avg} = T_c + (1-H) \cdot T_m $$ Where \(T_c\) is Cache Access Time and \(T_m\) is Miss Penalty.

H (Hit Ratio)# Hits / Total Accesses
1-H (Miss Ratio)# Misses / Total Accesses

3. Mapping Concepts & Address Splitting

How do we translate a Main Memory (MM) address to a Cache location? The Physical Address is split into fields.

General Address Structure

Physical Address bits = \(\log_2(\text{Main Memory Size})\)

[ TAG | SET/LINE INDEX | BLOCK/WORD OFFSET ]

4. Direct Mapping

The Logic

Each block of Main Memory maps to exactly one specific line in the Cache.

$$ i = k \pmod N $$
  • \(i\): Cache Line Number
  • \(k\): Main Memory Block Number
  • \(N\): Total Number of Cache Lines
Address Interpretation

Example: Cache 512KB, Block 64KB, MM 512MB

  • Offset: \(\log_2(64\text{KB}) = 16\) bits
  • # Lines: \(512\text{KB} / 64\text{KB} = 8\) lines
  • Line Index: \(\log_2(8) = 3\) bits
  • Tag: Remaining bits.

Visualization: K mod N

Contention: Block 0 and Block 4 fight for Line 0. This causes Conflict Misses.

5. Set Associative Mapping

A compromise between Direct and Fully Associative. Group cache lines into "Sets".

K-Way Set Associative

Each MM block maps to a specific Set, but can go into any Line within that Set.

$$ \text{Set } i = k \pmod S $$ $$ S = \frac{\text{Total Cache Lines}}{K} $$

Physical Address

[ TAG | SET INDEX | OFFSET ]

Set Index bits: \(\log_2(\text{Number of Sets})\)

Example Calculation: 2-Way Set Associative

Given: Cache 16 Lines, 2-Way.

  1. # Sets: \(16 / 2 = 8\) Sets.
  2. Mapping: Block \(k\) maps to Set \(k \pmod 8\).
  3. Inside that set, the block can occupy either of the 2 ways (slots).

Note: Requires Replacement Algorithm (like LRU) when the set is full.

6. Fully Associative Mapping

The Logic

No strict mapping function. Any MM block can go into ANY Cache Line.

Physical Address only has: [ TAG | OFFSET ].

Hardware Cost

Requires a comparator for every cache line to check Tags in parallel.

Expensive but 0 Conflict Misses.

7. Misses & Replacement Policies

The 3 C's (Types of Misses)

  • Compulsory (Cold): First access to a block. Cannot be avoided (unless pre-fetching). Reduced by larger Block Size.
  • Capacity: Cache is full. Reduced by increasing Cache Size.
  • Conflict: Mapping limitation (e.g., in Direct Mapping). Reduced by increasing Associativity.

Replacement Algorithms

Used in Set/Fully Associative when a Set/Cache is full.

  • FIFO: Replace the oldest block brought in.
  • LRU (Least Recently Used): Replace the block unused for the longest time. (Exploits temporal locality).
  • Random: Random selection.

8. Multilevel Caches (L1, L2, L3)

Modern CPUs use multiple levels to balance speed and size.

$$ T_{avg} = T_{L1} + M_{L1} \times T_{L2} + M_{L1} \times M_{L2} \times T_{MM} $$

Where \(M_{Lx}\) is the Miss Rate of that level.

Inclusion Property

\(L1 \subset L2\). All data in L1 must also be in L2.

Pros: Easier cache coherence.

Exclusion Property

\(L1 \cap L2 = \emptyset\). Data is in L1 OR L2, never both.

Pros: Maximizes total usable capacity.
