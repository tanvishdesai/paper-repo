1. System Overview

The Computer Organization & Architecture (COA) focuses on the structural relationships and functional operations of the computer system.

Core Components

CPU

The brain. Contains Registers, ALU, and Control Unit.

Registers

High-speed temporary storage (Flip-Flops). E.g., PC, IR, MAR, MBR, AC.

ALU

Hardware unit for Arithmetic (Add, Sub) and Logical (AND, OR) operations.

Control Unit

The supervisor. Generates timing and control signals to coordinate operations.

2. Common Bus System

Instead of connecting every component to every other component ($20$ components $\approx 200+$ connections), we use a Common Bus.

Multiplexer (MUX) Logic

The bus is constructed using Multiplexers.

  • If we have k registers of n bits each:
  • Number of MUX needed: $n$ (one for each bit position).
  • Size of each MUX: $k \times 1$ (k inputs selected by select lines).
  • Number of Select Lines: $S = \lceil \log_2 k \rceil$.

Data Transfer Micro-operation

To transfer data from Register A to Register B ($R_A \to R_B$):

  1. Select Register A: Set MUX Select lines to index of A.
  2. Place on Bus: Content of A appears on the Bus.
  3. Load Register B: Activate the Load (LD) or R_in signal of Register B.

3. Instruction Cycle

The operational sequence of the CPU: Fetch $\to$ Decode $\to$ Execute $\to$ Interrupt.

RTL: Register Transfer Language

Standard micro-operations for the basic cycles.

Fetch Cycle (Hardware Flow)
T1: PC → MAR
T2: M[MAR] → MBR; PC + 1 → PC
T3: MBR → IR

Note: Fetching instruction from memory to IR and incrementing PC.

Indirect Cycle (Operand Fetch)
T1: IR(Address) → MAR
T2: M[MAR] → MBR
T3: MBR → IR(Address)

Used when the address in instruction points to another address (pointer).

Interrupt Cycle
T1: PC → MBR
T2: SP → MAR; Vector_Address → PC
T3: MBR → Memory[MAR]

Saving return address (PC) to Stack and loading Interrupt Service Routine address.

4. Control Unit Design

The Control Unit (CU) generates control signals to activate micro-operations. There are two main approaches.

Comparison: Hardwired vs. Micro-programmed

Feature Hardwired CU Micro-programmed CU
Implementation Logic Gates, Flip-flops, Decoders (Hardware). Control Memory (ROM) storing micro-instructions (Software/Firmware).
Speed Fastest (Direct circuit execution). Slower (Memory access time).
Flexibility Rigid. Hard to modify. Flexible. Easy to update code.
Design Complexity Complex for large instruction sets. Systematic and simpler.
Architecture Used in RISC. Used in CISC.

Hardwired Logic Design

Control signals are expressed as Boolean functions of Instruction Decodes (I) and Timing Signals (T).

$$ \text{Signal}_{Ain} = T_1 \cdot I_1 + T_2 \cdot I_3 + \dots $$

This implies the signal $A_{in}$ is active during time $T_1$ for instruction $I_1$ OR time $T_2$ for instruction $I_3$.

5. Micro-Instruction Formats

In a Micro-programmed CU, control information is stored in words. The format determines how control signals are encoded.

Control Word Structure

Condition Select Branch Logic
Branch Address Next Address (CAR)
Control Field The Control Signals

Horizontal vs. Vertical Micro-programming

Horizontal (Decoded)

  • 1 bit per control signal.
  • No external decoder needed.
  • Long control words (High bit count).
  • Allows high parallelism.
  • Example: 50 Control Signals $\to$ 50 bits.

Vertical (Encoded)

  • Encoded bits. Requires Decoder.
  • Shorter control words.
  • Slower (Decoding delay).
  • Low parallelism.
  • Example: 50 Control Signals $\to \lceil \log_2 50 \rceil = 6$ bits.

Calculation: Control Memory Size

$$ \text{Size} = 2^{\text{CAR Size}} \times \text{Control Word Width} $$

If CAR is 10 bits, Control Memory has $2^{10} = 1024$ words.

6. Performance Metrics

Quantifying the speed of a processor.

Key Formulas

$$ \text{Cycle Time } (\tau) = \frac{1}{\text{Clock Frequency}} $$
$$ \text{Execution Time (ET)} = \text{Instruction Count (IC)} \times \text{CPI} \times \text{Cycle Time} $$

CPI: Cycles Per Instruction (Average).

$$ \text{MIPS} = \frac{\text{Clock Rate}}{\text{CPI} \times 10^6} $$

Million Instructions Per Second.

Example Calculation

Given: 100 Instructions. Each takes 6 cycles. Processor 1 GHz.

1. Cycle Time: $1 / 10^9 \text{ Hz} = 1 \text{ ns}$

2. Total Cycles: $100 \times 6 = 600$ cycles

3. Execution Time: $600 \times 1 \text{ ns} = 600 \text{ ns}$

Speedup / Gain

When comparing two designs (Old vs New):

$$ \text{Speedup} = \frac{\text{Performance}_{\text{new}}}{\text{Performance}_{\text{old}}} = \frac{\text{Execution Time}_{\text{old}}}{\text{Execution Time}_{\text{new}}} $$
