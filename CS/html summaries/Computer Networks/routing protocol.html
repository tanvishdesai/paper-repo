Static Routing

  • Routes are manually configured by the administrator.
  • Pros: No bandwidth usage for updates, secure.
  • Cons: No fault tolerance, difficult to scale.

Dynamic Routing

  • Routes are calculated automatically based on topology.
  • Pros: Scalable, handles failure automatically.
  • Cons: Uses bandwidth/CPU for updates.

2. Flooding

Flooding is a simple static routing algorithm where every incoming packet is sent through every outgoing link except the one it arrived on.

Visual Logic

graph LR A((A)) -->|Packet| B((B)) B -->|Copy 1| C((C)) B -->|Copy 2| D((D)) B -->|Copy 3| E((E)) style A fill:#bfdbfe style B fill:#fde68a

Analysis

Advantages Disadvantages
No Routing Table: Simple implementation. High Traffic: Creates congestion.
Reliable: If a path exists, packet finds it. Duplicate Packets: Receiver gets multiple copies.
Shortest Path: Guaranteed to find the fastest route (along with others). Loops: Infinite looping if no TTL is used.

3. Distance Vector Routing (DVR)

Also known as the Bellman-Ford Algorithm. Routers exchange knowledge about the network with their immediate neighbors.

Key Principle: "Tell your neighbors about the world."
$$ D_x(y) = \min_v \{ c(x,v) + D_v(y) \} $$
Where \(D_x(y)\) is cost from x to y, \(c(x,v)\) is cost to neighbor v, and \(D_v(y)\) is neighbor's distance to y.

The Process

  1. Initialization: Each router creates a table with distance to itself (0) and immediate neighbors (link cost). Distance to unknown nodes is \(\infty\).
  2. Exchange: Routers send their distance vectors to immediate neighbors.
  3. Update: Upon receiving a vector, a router recalculates routes using the Bellman-Ford equation.
Step-by-Step Calculation Example (Detailed)

Consider 3 nodes: A --(2)-- B --(3)-- C.

Step 1 (Local):
A knows: A=0, B=2, C=\(\infty\)
B knows: A=2, B=0, C=3
C knows: A=\(\infty\), B=3, C=0

Step 2 (Exchange - B sends to A):
A computes distance to C via B: \( Cost(A,B) + Dist(B,C) = 2 + 3 = 5 \).
Since \(5 < \infty\), A updates routing table for C to 5.

4. Problems in DVR

The Count-to-Infinity Problem

DVR converges slowly to "bad news" (link failures).

Good News Spreads Fast

When a link cost decreases or a node is added, the information propagates quickly because nodes immediately find a lower cost.

Bad News Spreads Slow

When a link fails or cost increases, nodes may cycle updates amongst themselves, slowly incrementing the cost towards \(\infty\).

Scenario: A --- B --- C

Suppose links have cost 1. C goes down (Cost to C becomes \(\infty\)).

sequenceDiagram participant B participant A Note over B: Link to C breaks Note over B: B still thinks A has a path to C (cost 2) B->>B: Updates route to C via A: 1 + 2 = 3 B->>A: "I can reach C with cost 3" A->>A: Updates route to C via B: 1 + 3 = 4 A->>B: "I can reach C with cost 4" Note right of A: This loops until infinity

This creates Infinite Looping and excessive traffic.

5. Solutions: Split Horizon

Rule: Do not send routing information about a destination back to the neighbor from whom you learned it.

"If B routes to C via A, B should not tell A that it has a path to C."

Mechanism

  • Prevents 2-node loops immediately.
  • Solves the Count-to-Infinity problem for linear/small loops.
  • Note: Split Horizon reduces chance of loops but does not solve the Convergence Problem entirely (especially in 3+ node loops).

Limitations

For complex network instability or larger loops, DVR still struggles. The ultimate solution for fast convergence is migrating to Link State Routing (OSPF).

6. Common Problem Patterns (GATE/Exam)

Key Insight: In DVR, routers initially only know their direct neighbors. Tables "stabilize" after \(N-1\) rounds (where N is longest path).
Problem 1: Route Stabilization
Scenario: A network with links having weights. After tables stabilize, how many links are unused?

Strategy:
  1. Draw the topology.
  2. Find the Shortest Path Tree (SPT) from every node to every other node (mentally or using Dijkstra logic, as stabilized DVR finds shortest paths).
  3. Identify edges that are never part of any shortest path.

Problem 2: Updating Vectors (The "F" Router)
Given: Router F has neighbors A, E, D, G with link delays 8, 10, 12, 6. F receives vectors from neighbors.

Logic: New \(D_F(X) = \min [ \text{Delay}(F,Neighbor) + \text{Vector}_{Neighbor}(X) ]\)

Calculation: Check every destination (A, B, C...) via every neighbor (A, E, D, G) and pick the minimum sum.
