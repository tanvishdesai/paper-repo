IPv4 Header & Fragmentation

Comprehensive Cheat Sheet for Computer Networks • Based on Lecture Notes 1-7

At a Glance

The Network Layer (L3) is responsible for logical addressing and routing. The fundamental unit is the Datagram (Packet). IP is a connectionless, unreliable protocol.

  • Protocol: IPv4 (32-bit addressing)
  • Scope: Host-to-Host delivery
  • Key Mechanism: Fragmentation allows large packets to traverse networks with smaller MTUs.
Encapsulation Hierarchy:
App Layer (Message) → Transport Layer (Segment) → Network Layer (Datagram) → Data Link Layer (Frame)

The IPv4 Header Format

The IPv4 header is 20 to 60 bytes long. It provides the necessary control information for routing and delivery.

Detailed Field Analysis

1. Control & Sizing

Field Description Math/Values
Version (VER) Identifies the IP version. Always 0100 (4) for IPv4. 0110 for IPv6.
Header Length (HLEN) Length of header in 4-byte words. Value: 5 to 15.
$$HeaderSize = HLEN \times 4 \text{ Bytes}$$
Min: $5 \times 4 = 20B$, Max: $15 \times 4 = 60B$.
Total Length Total size of the datagram (Header + Data). Range: $0$ to $2^{16}-1$ (65,535 Bytes).
$$DataSize = TotalLength - HeaderSize$$

2. Service & Reliability

Type of Service (8 bits): Originally defined as Priority (3 bits) + TOS (4 bits) + Unused (1 bit). Now commonly used for DiffServ.

D: Delay T: Throughput R: Reliability C: Cost

Time To Live (TTL): Prevents infinite looping. Decremented by 1 at each router (hop).

  • If TTL = 0, packet is discarded and ICMP Time Exceeded is sent to source.
  • Limits the lifespan of data in the network.

3. Protocol & Identification

Protocol (8 bits): Indicates which upper-layer protocol handles the data.

Fragmentation Mechanics

Why fragment? Hardware limits. Every network has a Maximum Transmission Unit (MTU) (e.g., Ethernet = 1500 Bytes). If Packet > MTU, it must be split.

Where? At Routers (intermediary devices). Reassembly happens ONLY at the Destination.

Fragmentation Fields

1. Identification (16 bits)

All fragments of the original datagram share the same ID. This allows the destination to group them together.

2. Flags (3 bits)

  • Bit 1: Reserved (Unused).
  • Bit 2 (DF - Don't Fragment):
    DF=1: Do not fragment. If Packet > MTU, discard and send ICMP error.
    DF=0: Fragmentation allowed.
  • Bit 3 (MF - More Fragments):
    MF=1: Not the last fragment. More are coming.
    MF=0: This is the last fragment (or the only fragment).

3. Fragment Offset (13 bits)

Indicates the position of this fragment's data in the original stream. The unit is 8-byte blocks.

$$ \text{Offset Value} = \frac{\text{Number of bytes ahead}}{8} $$

Critical Rule

The data payload size of every fragment (except the last one) must be divisible by 8.

Formulas & Overhead Calculation

1. Calculating Data in a Fragment

When MTU is given, the max data we can send in one fragment is:

$$ \text{MaxData} = \text{MTU} - \text{HeaderLength} $$

Constraint: If this is not the last fragment, $\text{MaxData}$ must be rounded down to the nearest multiple of 8.

2. Number of Fragments

$$ N = \lceil \frac{\text{Total Data Size}}{\text{Effective Data Per Fragment}} \rceil $$

3. Overhead & Efficiency

Every fragment gets its own IP header (usually 20B).

  • Total Overhead: $(N_{fragments} \times 20) \text{ Bytes}$
  • Efficiency: $$\eta = \frac{\text{Useful Data}}{\text{Total Data + Total Headers}} \times 100\%$$

Solved Problem Logic (Case Studies)

Case 1: Identifying Fragment Position

How do we know if a fragment is First, Middle, or Last?

  • First Fragment: Offset = 0 AND MF = 1
  • Middle Fragment: Offset > 0 AND MF = 1
  • Last Fragment: Offset > 0 AND MF = 0
  • Only Fragment (Unfragmented): Offset = 0 AND MF = 0
Case 2: Fragmentation Calculation

Given: IP Datagram = 4404 Bytes. Header = 20 Bytes. MTU = 1500 Bytes.

Step 1: Get Payload. $4404 - 20 = 4384$ Bytes of data.

Step 2: Max Payload per Fragment. $1500 - 20 = 1480$ Bytes. (Check: Is 1480 div by 8? Yes. $1480/8 = 185$).

Step 3: Split Data.

  • Frag 1: 1480 Bytes Data. Offset = 0. MF = 1.
  • Frag 2: 1480 Bytes Data. Offset = $1480/8 = 185$. MF = 1.
  • Remaining Data: $4384 - 1480 - 1480 = 1424$ Bytes.
  • Frag 3: 1424 Bytes Data. Offset = $(1480+1480)/8 = 370$. MF = 0.

Total Length of Frag 3: $1424 (\text{Data}) + 20 (\text{Header}) = 1444$ Bytes.

Case 3: Reassembly & Reconstruction

Scenario: Receiver gets a fragment with Offset=100, HLEN=5, Total Length=200.

  • Header Size: $5 \times 4 = 20$ Bytes.
  • Data in this fragment: $200 - 20 = 180$ Bytes.
  • Bytes ahead: $Offset \times 8 = 100 \times 8 = 800$ Bytes.
  • Sequence range for this fragment: Byte 800 to Byte $800 + 180 - 1 = 979$.

Relevant Formulas from Intro Slides

Terms

  • $T_t$ or $T_d$: Transmission Delay (Packet / Bandwidth)
  • $T_p$: Propagation Delay (Distance / Speed)
  • $a$: Ratio $T_p / T_t$
  • $RTT$: Round Trip Time ($2 \times T_p + T_t$)

Stop & Wait ARQ

Efficiency ($\eta$):

$$ \eta = \frac{1}{1 + 2a} $$

Sliding Window (GBN & SR)

Efficiency:

$$ \eta = \frac{N}{1 + 2a} $$

Where $N$ is window size.

Optimal Window Size

For 100% Utilization:

$$ N = 1 + 2a $$

In Bits: $Window(bits) = Bandwidth \times RTT$

Sequence Number Bits ($k$)

  • Stop & Wait: $N=1+1=2 \rightarrow k=1$ bit.
  • Go Back N: $W_s + W_r \le 2^k$ (where $W_r=1$). So $W_s \le 2^k - 1$.
  • Selective Repeat: $W_s + W_r \le 2^k$ (where $W_s=W_r$). So $W_s \le 2^{k-1}$.
