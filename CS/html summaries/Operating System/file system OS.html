File System & Device Management

Comprehensive notes on Disk Architecture, File System Implementation, Disk Scheduling Algorithms, and Multithreading Concepts.

Quick Recap: Working Set Strategy (Memory)

Before diving into FS, recall the Working Set Model from Memory Management:

  • Goal: Prevent thrashing by keeping the "locality of reference" pages in frames.
  • Working Set Window (\(\Delta\)): Time window to examine page references.
  • Formula: \(D = \sum WSS_i\). If \(D > M\) (Total Frames), system trashes.

1. Disk Physical Structure & Geometry

Hierarchy

graph TD D[Hard Disk] --> P[Platters] P --> S[Surfaces] S --> T[Tracks] T --> Sec[Sectors] Sec --> B[Bytes/Data]

Important Definitions

  • Platter: Circular disk, magnetic material. 2 surfaces per platter.
  • Track: Concentric circles on a surface.
  • Cylinder: Set of all tracks at the same arm position across all platters.
  • Sector: Smallest unit of data transfer (typically 512B or 4KB).

Disk Capacity Formula

$$ \text{Capacity} = \text{Heads} \times \text{Tracks/Surface} \times \text{Sectors/Track} \times \text{Bytes/Sector} $$

Disk Access Time Analysis

The time required to read/write data depends on three mechanical factors:

Component Definition Time Estimate
1. Seek Time Time to move the R/W head to the correct track (cylinder). 3ms - 10ms (Slowest)
2. Rotational Latency Time for the desired sector to rotate under the head. Avg = \( \frac{1}{2} \times \text{Time for 1 rotation} \)
3. Transfer Time Time to actually read the bits from the surface. \( \frac{\text{Data Size}}{\text{Transfer Rate}} \)
$$ \text{Total Access Time} = \text{Seek Time} + \text{Rotational Latency} + \text{Transfer Time} $$

2. Logical File System

The Layered File System

graph BT HW[Hardware / Devices] --> IO[I/O Control] IO --> Basic[Basic File System] Basic --> Org[File Organization Module] Org --> Logical[Logical File System] Logical --> App[Application Programs]

Directory Structures

  • Single-Level: All files in one folder. Naming conflicts!
  • Two-Level: User File Directory (UFD) inside Master File Directory (MFD).
  • Tree-Structured: Standard hierarchy. Subdirectories allowed.
  • Acyclic Graph: Allows shared files (links/aliases). No cycles.
  • General Graph: Allows cycles. Needs Garbage Collection.

File Control Block (FCB)

Also known as the Inode in Unix. Contains metadata:

  • File Permissions
  • Dates (Create, Access, Write)
  • Owner/Group ID
  • Size
  • Pointers to Data Blocks

3. Allocation Methods

How do we assign disk blocks to files?

Method 1: Contiguous Allocation

File occupies a set of contiguous blocks on the disk.

  • Directory Entry: Start Address, Length.
  • Pros: Excellent Read Performance (1 seek), Simple.
  • Cons: External Fragmentation, Growing files is difficult.
Method 2: Linked Allocation

Each block contains a pointer to the next block. Scattered anywhere.

  • Directory Entry: Start Pointer, End Pointer.
  • Pros: No External Fragmentation, File size can grow easily.
  • Cons: Slow Sequential Access (lots of seeks), No Random Access, Reliability (link breakage).
Method 3: Indexed Allocation

Brings all pointers together into one block: the Index Block.

  • Directory Entry: Address of Index Block.
  • Pros: Supports Random Access, No External Fragmentation.
  • Cons: Overhead of Index Block (wasted space for small files).

4. Unix Inode & FAT

Unix Inode Structure

Hybrid approach to handle small and very large files efficiently.

graph LR Inode[Inode] Direct[12 Direct Ptrs] Single[1 Single Indirect] Double[1 Double Indirect] Triple[1 Triple Indirect] Inode --> Direct Inode --> Single Inode --> Double Inode --> Triple Direct --> Data1[Data Block] Single --> Index1[Index Block] --> Data2[Data Block] Double --> Index2[Index Block] --> Index3[Index Block] --> Data3[Data Block]

FAT (File Allocation Table)

Used in DOS/Windows. A table acts as a Linked List index.

  • Structure: One entry per disk block.
  • Content: Entry \(i\) contains the index of the next block in the file.
  • End of File: Marked with a special value (e.g., -1 or EOF).
  • Drawback: Entire table must be loaded into RAM for performance.

Max File Size Calculation (Unix Inode)

Given: Block Size (\(B\)), Address Size (\(A\)).
Number of addresses per block \(N = B / A\).

$$ \text{Max Size} = \underbrace{12 \times B}_{\text{Direct}} + \underbrace{N \times B}_{\text{Single}} + \underbrace{N^2 \times B}_{\text{Double}} + \underbrace{N^3 \times B}_{\text{Triple}} $$

5. Disk Scheduling Algorithms

Goal: Minimize Seek Time (Head Movement).

Algo Description Pros/Cons
FCFS First Come First Serve. Process requests in order. Fair Slow/High Seek
SSTF Shortest Seek Time First. Pick closest request to current head. Low Avg Seek Starvation
SCAN Elevator. Move end-to-end, servicing requests. Reverse at end. Good Throughput Long wait for ends
C-SCAN Circular SCAN. Move one way only. Return to start immediately without servicing. Uniform Wait Time
LOOK Like SCAN, but only goes as far as the last request (doesn't hit end). Saves unnecessary movement
C-LOOK Like C-SCAN, but only goes to last request, then jumps to first request. Most Practical

Visualization Logic

Imagine the Disk Queue: 98, 183, 37, 122, 14, 124, 65, 67. Head at 53.

6. Threads & Multithreading

Process vs. Thread

A Thread is a Light-Weight Process (LWP). It is a basic unit of CPU utilization.

graph TD subgraph Process Memory Code[Code - SHARED] Data[Data - SHARED] Files[Files - SHARED] T1[Thread 1 Stack/Regs] T2[Thread 2 Stack/Regs] T3[Thread 3 Stack/Regs] end

Benefits of Multithreading

  1. Responsiveness: UI stays active even if one thread blocks.
  2. Resource Sharing: Threads share memory/code by default (efficient).
  3. Economy: Context switching threads is cheaper than processes.
  4. Scalability: Utilizing Multicore Architectures.

User vs. Kernel Level Threads

Feature User-Level Threads (ULT) Kernel-Level Threads (KLT)
Management User Library (Pthreads, Java) OS Kernel
Speed Fast (No System Calls) Slower (System Calls required)
Blocking If one thread blocks, entire process blocks. Independent. If one blocks, others run.
Kernel View Kernel sees 1 Process. Kernel sees individual threads.

Multithreading Models

  • Many-to-One: Many ULT mapped to 1 KLT. (Solaris Green Threads). Efficient but no true parallelism.
  • One-to-One: 1 ULT mapped to 1 KLT. (Linux, Windows). True concurrency, higher overhead.
  • Many-to-Many: Multiplexing many ULTs to a smaller/equal number of KLTs.
