Operating Systems: Memory Management

Comprehensive notes on Address Binding, Paging, Segmentation, and Virtual Memory. Synthesized from Lecture Series 1-12.

1. Memory Basics & Abstract View

Logical vs. Physical Address Space

  • Logical Address (Virtual): Generated by the CPU. Used by the program.
  • Physical Address: Actual location in the Main Memory (RAM).
  • MMU (Memory Management Unit): Hardware device that maps logical to physical addresses at run-time.

Definitions

  • Word: Basic unit of data (e.g., 4 Bytes).
  • Addressability: No. of wires needed to address memory. $N = 2^n$ (n bits).
  • Goal: Efficient utilization (minimize wastage) and Protection (isolation).

2. Loading, Linking & Binding

Loading Techniques

Static Loading: Entire program loaded into memory before execution. Inefficient

Dynamic Loading: Routine loaded only when called. Better space utilization. Efficient

Linking Techniques

Static Linking: Libraries combined by linker into binary image. Larger size.

Dynamic Linking: Linking postponed until execution time. Shared libraries (.dll, .so). Saves disk/memory.

3. Contiguous Memory Allocation

Fragmentation

  • Internal Fragmentation: Allocated memory is slightly larger than requested memory. Difference is wasted inside the partition.
  • External Fragmentation: Total free memory is enough for a request, but it's not contiguous.

Compaction

Technique to solve External Fragmentation by shuffling memory contents to place all free memory together.
Only possible if relocation is dynamic (Run-time). Expensive.

Partitioning Strategies

Fixed Partitioning (MFT) vs Variable Partitioning (MVT)
Fixed (Static) Partitioning
  • Memory divided into fixed-sized partitions.
  • Degree of multiprogramming is limited by partition count.
  • Suffers from Internal Fragmentation.
Variable (Dynamic) Partitioning
  • Partitions created dynamically to fit process size exactly.
  • No Internal Fragmentation.
  • Suffers from External Fragmentation.

Allocation Algorithms

Algorithm Strategy Pros/Cons
First Fit Allocate the first hole that is big enough. Fastest.
Best Fit Allocate the smallest hole that is big enough. Produces smallest leftover hole. Slow (must search list).
Worst Fit Allocate the largest hole. Produces largest leftover hole (potentially usable). Slow.

4. Paging

A non-contiguous allocation scheme. Physical memory is divided into fixed-size blocks called Frames. Logical memory is divided into blocks called Pages.

$$ \text{Page Size} = \text{Frame Size} $$

Address Translation Architecture

CPU generates Logical Address (LA) split into:

  • p (Page Number): Index into Page Table.
  • d (Page Offset): Displacement within the page.
graph LR CPU[CPU] -- "p | d" --> MMU MMU -- "Lookup p" --> PT[Page Table] PT -- "Returns f" --> ADD[Combine f | d] ADD --> PHY[Physical Memory] style PT fill:#fff,stroke:#333,stroke-dasharray: 5 5

Key Formulas

  • If $LAS = 2^m$ bytes and Page Size = $2^n$ bytes:
  • Page Number (p) bits: $m - n$
  • Offset (d) bits: $n$
  • Number of Pages: $2^{m-n}$
  • Page Table Size: $\text{No. of Pages} \times \text{Entry Size (PTE)}$

5. Translation Lookaside Buffer (TLB)

The Page Table is stored in main memory. This means every data access requires two memory accesses (one for PT, one for Data). The TLB is a fast associative hardware cache to solve this.

Effective Memory Access Time (EMAT)

$$ EMAT = H(c + m) + (1-H)(c + 2m) $$

Where H = Hit Ratio, c = TLB Access Time, m = Main Memory Access Time.

6. Advanced Paging Structures

Multi-Level Paging

Used when the Page Table is too large to fit contiguously in memory. We page the page table.

  • Goal: Avoid allocating contiguous memory for PT.
  • Cost: More memory accesses per request (e.g., 2-level = 3 accesses).
  • Outer PT: Fits in 1 frame usually.

Inverted Page Table

One entry for each physical frame of memory, not each logical page.

  • Size: Proportional to Physical Memory (RAM), not Logical Address Space.
  • Cons: Hard to search (requires Hashing). Shared pages difficult.

Hashed Page Table

Common in address spaces > 32 bits. The Virtual Page Number is hashed into a page table. Each entry contains a linked list of elements.

7. Segmentation

A memory management scheme that supports the user view of memory. A program is a collection of segments (Main, Stack, Symbol Table, etc.).

Logical Address

< Segment-Number, Offset >

Map defined by Segment Table.

Segment Table Entry (STE)

  • Base: Starting physical address.
  • Limit: Length of the segment.

Protection

Hardware must check: if (offset < limit). If false, TRAP (Addressing Error).

8. Virtual Memory & Demand Paging

Separation of user logical memory from physical memory. Allows execution of processes that are not completely in memory. Logical Address Space > Physical Address Space.

Demand Paging

Bring a page into memory only when it is needed. Less I/O, less memory needed, faster response.

Page Fault Handling Steps

  1. Reference to page is invalid or not in memory (Trap to OS).
  2. OS checks internal table: Invalid ref $\to$ Abort. Just not in memory $\to$ Continue.
  3. Find a free frame.
  4. Swap page into frame from disk.
  5. Reset tables (Valid bit = 1).
  6. Restart instruction.
$$ EMAT = (1-p) \times ma + p \times (\text{Page Fault Service Time}) $$

Where $p$ is Page Fault Rate ($0 \le p \le 1$).

9. Page Replacement Algorithms

When a page fault occurs and memory is full, we must victimize a page.

Algorithm Description Note
FIFO Replace oldest page. Suffers from Belady's Anomaly (More frames $\ne$ fewer faults).
Optimal (OPT) Replace page that will not be used for longest time. Impossible to implement (requires future knowledge). Used as benchmark.
LRU Replace page that has not been used for longest time. Good approximation of OPT. Uses Stack or Counters. No Belady's Anomaly.
Second Chance FIFO + Reference Bit. Give page a second chance if Ref Bit = 1. Clock Algorithm implementation.

Belady's Anomaly

Specifically in FIFO: Increasing the number of page frames results in an increase in the number of page faults for certain access patterns.

10. Thrashing

A process is thrashing if it is spending more time paging (swapping in/out) than executing.

Cause

Degree of Multiprogramming is too high. Total memory demand exceeds physical memory. CPU utilization drops drastically.

Working Set Model

Based on Locality of Reference. The OS tracks the "working set" of pages a process is currently using. If sum of working sets > total memory, suspend a process.
