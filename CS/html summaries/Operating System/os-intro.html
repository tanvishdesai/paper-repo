1. What is an Operating System?

The OS acts as the fundamental interface between the user/software and the computer hardware. It can be viewed through multiple lenses:

graph TD U[User 1] -->|Uses| App1[Compiler/Editor] U2[User 2] -->|Uses| App2[Web Browser] App1 -->|System Calls| OS[Operating System] App2 -->|System Calls| OS OS -->|Controls| HW[Hardware: CPU, RAM, I/O] style OS fill:#2563eb,color:#fff,stroke:#333,stroke-width:2px style HW fill:#0f172a,color:#fff

1. Resource Manager

Manages allocation and de-allocation of CPU, Memory, Files, and I/O Devices. It decides who gets what, when, and for how long.

2. Control Program

Controls the execution of user programs and operations of I/O devices to prevent errors and improper use of the computer.

💡 The Government Metaphor: An OS acts like a government. It creates an environment where other programs can do useful work, but it performs no useful "business" function itself (like producing goods). It simply provides the infrastructure and order.

2. Functions & Goals

The primary goal depends on the type of system (PC vs Mainframe).

Goal Target Audience Description
Convenience Personal Computers (Windows, Mac) Make the computer easy to use. User-friendly interface (GUI). Efficiency is secondary.

3. Computer System Architecture

Von Neumann

The Von Neumann Model

Programs must be loaded into Main Memory (RAM) to be executed. The CPU follows the fetch-decode-execute cycle.

  • Stored Program Concept: Instructions and Data are stored in the same memory.
  • Execution: Sequential (Program Counter -> Instruction Register).

Memory Hierarchy

Trade-off between Speed, Size, and Cost.

Note the massive gap between RAM (nanoseconds) and Disk (milliseconds). This gap drives the need for Multiprogramming.

4. Evolution: Uniprogramming vs. Multiprogramming

Uniprogramming (Batch Systems)

Only one process in memory at a time. If the process does I/O, the CPU sits IDLE.

Drawback: Poor CPU utilization.

$$ \text{Throughput} = \frac{\text{Number of jobs}}{\text{Total time}} $$
Multiprogramming (The Game Changer)

Definition: Ability to keep multiple programs in memory simultaneously. When one job waits for I/O, the OS switches the CPU to another job.

  • Goal: Maximize CPU Utilization.
  • Requirement: Needs context switching.

Comparison of OS Types

Type Mechanism Key Feature
Batch OS Jobs grouped in batches. Non-interactive. Difficult to debug.
Multiprogramming Multiple jobs in RAM. CPU switches on I/O wait. Increases Throughput.
Timesharing (Multitasking) Logical extension of Multiprogramming. CPU switches rapidly (Time Quantum). Interactivity. Response time is key. (User feels they have dedicated CPU).
Real-Time OS (RTOS) Strict time constraints (Deadlines). Hard RT: No delay (Missile). Soft RT: Minor delay ok (Video stream).

5. Architectural Requirements for Multiprogramming

Important

To safely run multiple programs, hardware must support specific features:

A. Dual Mode Operation

Hardware provides at least two modes of operation to protect the OS from errant user programs.

  • User Mode (Bit = 1): Restricted. Cannot access hardware directly.
  • Kernel/Monitor Mode (Bit = 0): Privileged. Can execute all instructions.
stateDiagram-v2 direction LR state "User Mode (1)" as UM state "Kernel Mode (0)" as KM UM --> KM : System Call / Trap / Interrupt KM --> UM : Return from System Call note right of KM Privileged Instructions (I/O, Memory Mgmt) end note

B. DMA (Direct Memory Access)

Allows I/O devices to transfer data directly to Memory without burdening the CPU. Essential for Multiprogramming efficiency.

C. Memory Protection

MMU (Memory Management Unit): Translates Logical Addresses to Physical Addresses and ensures a user program doesn't access memory owned by the OS or another user.
