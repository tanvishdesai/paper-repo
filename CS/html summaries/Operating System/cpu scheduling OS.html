1. Scheduling Fundamentals

Process Lifecycle

A process execution consists of a cycle of CPU Execution and I/O Wait.

graph LR A[Load Store] --> B(CPU Burst) B --> C{Wait for I/O} C --> D(I/O Burst) D --> E[Store Increment] E --> F(CPU Burst)
CPU Bound Process Performs lots of computations. Very long CPU bursts.
I/O Bound Process Performs lots of I/O. Short CPU bursts followed by I/O waits.

Key Timers & Formulas

Arrival Time (AT) Time at which the process enters the Ready Queue.
Burst Time (BT) Time required by the process for CPU execution.
Completion Time (CT) Time at which the process completes execution.

Turn Around Time (TAT)

Total time spent in the system.

$$TAT = CT - AT$$
$$TAT = \text{Burst Time} + \text{Waiting Time}$$

Waiting Time (WT)

Total time spent waiting in the Ready Queue.

$$WT = TAT - (BT + I/O BT)$$
If no I/O Burst, WT = TAT - BT

2. Scheduling Criteria

The goal of the scheduler is to balance these often conflicting metrics.

Criteria Goal Description
CPU Utilization Maximize Keep the CPU as busy as possible (0% to 100%).
Throughput Maximize Number of processes completed per unit time ($ \eta = \frac{n}{L} $).
Turnaround Time Minimize Time from submission to completion.
Waiting Time Minimize Sum of periods spent waiting in the ready queue.
Response Time Minimize Time from submission until the first response is produced.

Schedule Length (L)

Total time taken to complete all $n$ processes as per schedule.

$$L = \max(CT) - \min(AT)$$

% CPU Idleness: $ \frac{\text{Total Idle Time}}{L} \times 100 $

3. First Come First Serve (FCFS)

Non-Preemptive

Mechanism

Processes are executed in the order of their Arrival Time (AT). The simplest algorithm.

  • Selection Criteria: Arrival Time
  • Tie Breaker: Lower Process ID

Pros & Cons

  • ✅ Simple to implement (FIFO Queue).
  • ❌ Convoy Effect: Short processes wait behind a long CPU-bound process.
  • ❌ Not suitable for time-sharing systems.
Example: FCFS Calculation

Input: P1 (AT:0, BT:2), P2 (AT:1, BT:2), P3 (AT:5, BT:3)

P1 2
P2 4
IDLE 5
P3 8
Note: CPU is idle between time 4 and 5 because P3 arrives at 5.

4. Shortest Job First (SJF) & SRTF

SJF (Non-Preemptive)

Non-Preemptive

Among processes in the Ready Queue, select the one with the Least Burst Time.

  • Criteria: Burst Time
  • Optimal: Gives minimum average Waiting Time.

SRTF (Preemptive SJF)

Preemptive

Shortest Remaining Time First. If a new process arrives with a shorter burst than the current remaining time, preempt.

  • Also known as "Shortest Process Next" (SPN).
  • Checks RQ at every arrival.

Problems with SJF/SRTF

Starvation Longer processes may wait indefinitely if short processes keep arriving.
Implementation It is practically impossible to know the Burst Time of a process before execution. Used mainly as a benchmark.
Comparison: SJF vs SRTF Example

Input: P1 (AT:0, BT:5), P2 (AT:1, BT:2)

SJF (Non-Preemptive)

P1 starts at 0. Since it's non-preemptive, it runs fully to 5. Then P2 runs.

P1 5
P2 7

SRTF (Preemptive)

P1 runs from 0 to 1. At t=1, P2 arrives (BT=2). P1 remaining=4. Since $2 < 4$, P2 preempts P1.

P1 1
P2 3
P1 7

5. Priority & HRRN

Priority Scheduling

Processes are assigned a priority number (Integer). The CPU is allocated to the process with the highest priority.

  • Modes: Can be Preemptive or Non-preemptive.
  • Static Priority: Assigned at creation. leads to starvation.
  • Dynamic Priority: Changes at runtime to achieve system goals (e.g., "Aging").
Aging Algorithm: Increase the priority of processes waiting in the Ready Queue at regular intervals to prevent starvation.

HRRN (Highest Response Ratio Next)

Non-Preemptive

Designed to favor shorter jobs but limit the waiting time of longer jobs to prevent starvation.

Criteria: Response Ratio

$$ \text{Response Ratio} = \frac{W + S}{S} $$

Where $W = \text{Waiting Time}$, $S = \text{Service/Burst Time}$.

As $W$ increases, the Ratio increases, eventually giving the long process a high enough priority.

LRTF (Longest Remaining Time First)

Preemptive

Opposite of SRTF. Favors CPU-bound processes. Leads to high average TAT and WT.

  • Tie Breaking: If processes have equal BT, prefer lowest Process ID.
  • Often results in context switching between processes until all finish simultaneously.

6. Round Robin (RR)

Preemptive

Designed for Time-Sharing Systems. A Time Quantum (TQ) is defined. The Ready Queue is treated as a circular queue.

  • Criteria: Arrival Time + Time Quantum.
  • Goal: Improve interactiveness/response time.
graph LR RQ[Ready Queue] -- Dispatch --> CPU[CPU Execution] CPU -- Completed --> Term[Terminated] CPU -- Time Expired --> RQ CPU -- I/O Request --> Wait[I/O Wait]

Impact of Time Quantum ($TQ$)

  • If $TQ$ is very large: Becomes FCFS.
  • If $TQ$ is very small: Context Switching Overhead becomes too high, reducing effective CPU utilization.

Context Switch Overhead ($\delta$)

Time taken to save the state of the old process and load the state of the new process.

$$ \text{Useful CPU Time} = \text{Total Time} - (N \times \delta) $$

7. Predicting Burst Times

Since SJF requires knowing Burst Time in advance (which is impossible), we estimate it using past history.

Exponential Averaging (Aging)

Predicts the next burst time ($\tau_{n+1}$) based on the actual previous burst ($t_n$) and the previous prediction ($\tau_n$).

$$ \tau_{n+1} = \alpha t_n + (1 - \alpha)\tau_n $$
  • $\tau_{n+1}$: Predicted value for next burst.
  • $t_n$: Actual length of $n^{th}$ CPU burst.
  • $\alpha$: Weighting factor ($0 \le \alpha \le 1$). Usually $\alpha=0.5$.
Math Deep Dive: Recurrence Expansion

If we expand the formula, we see it considers the entire history, but recent history has more weight:

$$ \tau_{n+1} = \alpha t_n + \alpha(1-\alpha)t_{n-1} + \alpha(1-\alpha)^2 t_{n-2} + ... $$
