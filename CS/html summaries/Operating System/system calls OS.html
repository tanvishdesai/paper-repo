System Calls & Advanced Memory

High-density notes on Kernel interfaces, Process Control (fork), Inverted/Segmented Paging, and Synchronization Monitors.

1. System Calls Overview

Definition: A programmable interface (API) that allows user-level applications to request services from the Operating System kernel. It is the only entry point into the Kernel Mode.

Key Concepts

  • User Mode: Restricted access. Executing normal application code.
  • Kernel Mode: Privileged access. Executing OS instructions.
  • Context Switch: Triggered by a software interrupt (Trap) when a system call is made.

APIs vs Direct Calls

Programmers rarely use raw system calls. They use High-Level APIs:

  • Win32 API (Windows)
  • POSIX API (Unix, Linux, MacOS)
  • Java API (JVM)

Example: printf() (C Library) → calls write() (System Call).

Implementation Details

Example: Handling a read(fd, buffer, nbytes) call.

  1. Push parameters (nbytes, buffer, fd) onto the stack.
  2. Call the library function read.
  3. Library puts the System Call Number into a register.
  4. Execute TRAP instruction to switch to Kernel mode.
  5. Kernel Dispatcher reads the number from the register.
  6. Look up the handler address in the System Call Table.
  7. Execute the system call handler.
  8. Return control to the user library wrapper.

Parameter Passing Methods

1. Registers

Simplest method. Parameters are loaded directly into CPU registers.

Limitation: Number of registers is limited.

2. Block/Table

Parameters stored in a block in memory. The address of the block is passed in a register.

Used by: Linux, Solaris.

3. Stack

Parameters pushed onto the stack by the program and popped off by the OS.

Benefit: No limit on number/length of parameters.

2. The fork() System Call

Mechanism

  • Creates a new process (Child) which is an exact duplicate of the calling process (Parent).
  • Copy-on-Write: Data is duplicated, but code is shared (until modified).
  • Execution continues from the next instruction after fork() in both processes.

Return Values

  • Negative (-1): Creation failed.
  • Zero (0): Returned to the newly created Child Process.
  • Positive (PID): Returned to the Parent Process (PID of the child).
Formula: If fork() is called \( n \) times sequentially:
  • Total Processes Created = \( 2^n \)
  • Total Child Processes Created = \( 2^n - 1 \)

Fork Practice Patterns

Case 1: Sequential Fork

main() {
  fork(); // L1
  fork(); // L2
  fork(); // L3
  printf("Hello");
}

Output: "Hello" printed 8 times.

3. Inverted Paging

Designed to reduce the massive memory overhead of Page Tables in modern 64-bit systems with large virtual address spaces.

Concept

  • Traditional Paging: One Page Table per process. (Space overhead is high).
  • Inverted Paging: One global Page Table for the entire system.
  • Entry Structure: <Process ID, Page Number, Offset>
  • Mapping: Search the table for (PID, p). The index \( i \) of the match becomes the Physical Frame Number.

Downside: Searching is slow (linear). Solved using Hash Tables.

Memory Access Time: In Inverted Paging (without hashing), access time is NOT constant because linear search might be required. With Hashing, it is close to \(O(1)\) but collisions can occur.

4. Segmented Paging

Combines Segmentation (for logical view/protection) and Paging (to remove external fragmentation).

Architecture

The Logical Address is divided into: Segment Number (s) + Page Number (p) + Offset (d).

flowchart LR CPU[Logical Address
s | p | d] ST[Segment Table] PT[Page Table] PM[Physical Memory] CPU -- s --> ST ST -- Base Address of PT --> PT CPU -- p --> PT PT -- Frame Number f --> AddrCalc((f + d)) AddrCalc --> PM

Calculations (Example)

Given: Virtual Address Space = 4GB, Page Size = 8KB, Segment Table Entries = 256 (i.e., 256 segments per process).

  • Page Offset: \( 8KB = 2^{13} \rightarrow 13 \) bits.
  • Segment Number: \( 256 = 2^8 \rightarrow 8 \) bits.
  • Remaining bits (Page Number): Total bits \( (4GB = 2^{32}) \rightarrow 32 \).
    \( p = 32 - 8 - 13 = 11 \) bits.

Overhead: Requires multiple memory accesses (Segment Table + Page Table + Data) if TLB is not used.

5. Synchronization Mechanisms

Monitors

A high-level synchronization construct (abstract data type).

  • Encapsulation: Groups shared data, procedures, and initialization code.
  • Mutual Exclusion: Only one process can be active within the monitor at a time.
  • Condition Variables: x.wait() and x.signal() used to delay/resume processes.

Example: Dining Philosophers problem solution.

Shared Pages

Reentrant Code: Pure code (read-only) that does not modify itself. Can be shared by multiple processes (e.g., text editors, compilers, window systems).

  • Private Data: Each process keeps its own copy of data variables.
  • Shared Text: One copy of code in memory, mapped to multiple virtual address spaces.

Buddy System

A memory allocation algorithm that divides memory into partitions of power-of-2 sizes to minimize external fragmentation while allowing easy coalescing.
